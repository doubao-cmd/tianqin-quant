## ⚠️ 命名澄清（防自欺，写在最前面）

**本策略不是「布林带策略」，是「单均线穿越 + 多空双向」。**

布林带 = 中轨(MA) ± k×标准差。用户规则**只用了中轨**，上轨/下轨/k/标准差**全程不参与**。
⇒ 它等价于 `收盘价 vs MA20` 的穿越。**故命名「中轨趋势持有」**，不叫「布林带」，
避免与 07_布林带（完整三轨）混淆。

## 一、策略实质（三句实话）

1. **剥掉皮就是单均线穿越**：`want = +1 if 收盘 > MA20 else -1`。
2. **「永远在场」的翻转策略**：多空镜像合起来 = 中轨上方持多、下方持空，**空仓只存在于穿越那一瞬间**。
   ⇒ 单腿常驻趋势跟踪，不择时进出。
3. **★ engine 里已有一个「方向相反」的姊妹策略**：`lib/engine.py` L542 `rev_signal`（03 均值回归用），
   逻辑是「收盘 < 均值 → 做多」= 逆势。**本策略是它的镜像**（顺势）。
   两条腿的**换手次数完全相同**（穿越次数相同），只是持仓方向对调。

   `rev_signal` 的 docstring 已预先警示这类代价：
   > ⚠️ 换手 = 均线穿越次数，是**本项目所有策略里最高的**，成本会吃掉相当一部分毛利。

   **此警示对本策略同样成立**（方向对调不改变换手次数）。

## 二、信号定义（日线 K 线，只用已收盘数据）

**信号函数**（engine `signal_kind="trendhold"` 路径，目标仓位式）：

```python
def trend_hold_signal(cur_dir, close_now, mid_now):
    """中轨趋势持有 —— 顺势版（与 rev_signal 方向相反）。"""
    if mid_now != mid_now or close_now != close_now:   # NaN 守卫
        return cur_dir
    if close_now > mid_now:
        return 1        # 站上中轨 -> 持多
    if close_now < mid_now:
        return -1       # 跌破中轨 -> 持空
    return cur_dir      # 恰好相等 -> 维持
```

| 项 | 值 | 来源 |
|---|---|---|
| K 线周期 | **日线（86400 秒）** | 用户指定 |
| 均线 | **MA20（收盘价简单均值）** | 用户指定 |
| 方向 | 多空双向（永远在场） | 用户指定 |
| 输入取值 | 一律 `.iloc[-2]`（**刚收盘那根**） | 规则1 强制 |
| 成交时点 | **信号根收盘后、下一根开盘成交** | 规则1 强制 |

**镜像关系对照**：

| 条件 | 本策略（顺势） | rev_signal（逆势） |
|---|---|---|
| 收盘 > MA20 | 持**多** | 持**空** |
| 收盘 < MA20 | 持**空** | 持**多** |

## 三、入场 / 出场

**本策略「入场」与「出场」是同一个动作**（翻转）：

- 空仓/反向持仓时，收盘站上中轨 → 目标 `+1`（开多/反手多）
- 空仓/反向持仓时，收盘跌破中轨 → 目标 `-1`（开空/反手空）
- 持仓中且方向未变 → 目标不变，**不下单**（不重复交易）

★ 因为 `want` 恒为 ±1，**本策略没有「平仓后空仓等待」的状态**。

## 四、止损（★ 第一轮不启用 —— 裸版）

**用户原始规则里没有止损**，出场完全靠「中轨穿越」。

**第一轮跑裸版（用户 2026-10-12 拍板「先跑裸版」）**：

| 项 | 第一轮 | 备注 |
|---|---|---|
| 价格止损（2×ATR） | ❌ 不加 | 留第二轮，单变量 |
| 时间止损（20 根） | ❌ 不加 | 留第二轮，单变量 |

**为什么不第一轮就加**（写给未来的自己看）：
1. 一次加两个出场条件 + 原规则 = **三个出场口共存**，跑出来不管正负都**归因不出来是哪条起作用**（违反规则4）。
2. 项目的核心问题是「**MA20 穿越本身有没有 edge**」。若无 edge，加止损救不回来（止损只改变亏损分布形状，不产生 edge）。
3. 06 MA13 的实测教训：时间止损与价格止损表现**方向相反**（时间 +9,440 / 价格 −17,620），两个一起加很可能互相打架。

**第二轮若裸版失败**：可单变量加 2×ATR 止损 或 时间止损 20 根（**一次只加一个**），
但需**重新立卡或在变更记录留痕**，且 IS 样本视为已污染。

### ⚠️ 实跑口径修正（2026-10-12，必须记录）

**预注册卡原写「手数 = 波动率预算 1%」，实际执行是「固定 1 手」。**

- **根因**：`_risk_budget_hand`（engine L359-362）在 `stop_mult <= 0` 时**直接返回 `hand_min`**；
  本卡裸版 `atr_stop_mult = 0.0` ⇒ 分母 `0 × ATR × 乘数 = 0` ⇒ 触发 NaN/非正防护 ⇒
  手数退化为 **1 手**。
- **本质**：「波动率预算」需要**止损距离**当风险刻度，而「裸版」没有止损
  ⇒ **两者在 engine 里天然互斥**。这是起草时的疏漏，现已确认。
- **影响评估：不改变结论**。固定 1 手反而更干净（盈亏纯粹由信号质量决定）；
  若真按波动率预算执行（基准 8 手），手数与亏损都会放大数倍。
- **本卡第一轮口径如实记为「固定 1 手」。**
  （第二轮若要真跑波动率预算，须同时启用 `atr_stop_mult > 0` 的止损 —— 但那已属另一轮改动。）

## 十二、第二轮实验：加 2×ATR 止损（单变量，2026-10-12）

**用户指令**：「08 有没有时间止损，加上 2atr 止损试试，跑一个品种就行」

**先回答**：08 是第一轮**裸版**，**既无价格止损也无时间止损**（`atr_stop_mult=0.0`）。
另：`run_backtest` **不支持时间止损**（该能力只在布林带入口 `run_backtest_boll` 的
`time_stop_bars` 上）⇒ 要加时间止损**必须改 engine**，且它与 2ATR 是**两个变量**，
一起加就归因不出来 ⇒ **本轮只做 2ATR（严格单变量）**。

**★ 隔离变量**：直接把 `atr_stop_mult` 从 0 改成 2.0 会**连带**把「固定 1 手」变成
「波动率预算 2~8 手」（因为 `_risk_budget_hand` 用 `stop_mult` 当分母）
⇒ 故同步置 `risk_pct=0`，**手数保持固定 1 手**，做到只改一处。

- 品种：**豆粕 M**（成本最低 11.5 元/手、毛盈亏≈0，是三者中最中性的基线）
- 区间 / 成本 / 手数 / 滑点：与裸版**逐项相同**
- 入口：`策略/08_中轨趋势持有/回测/豆粕/中轨趋势_回测_实验2ATR止损.py`

| 平均亏损 | **−523** | **−532** | **没变小，反而略变大** |
| 盈利笔数 / 亏损笔数 | 50 / 124 | 49 / 126 | −1 / +2 |

⇒ **恶化几乎全部来自毛盈亏（−2,700），而成本几乎没变。**
⇒ **止损既没减少交易、也没让单笔亏得更少。**

### ★ 机制（从日志实录取得，不是推测）

```
[止损] 触及ATR止损 -> 平空    止损线 2566.29（即平在 2566）
[信号] 目标 +1 手（多）        触发价 2628.00      ← 紧接着就要反手做多
```

**止损把仓位平在了 2566，而不设止损、等 MA 反手时平仓价是 2628 —— 差 62 点 = 620 元/手。**

原因：本策略是「**永远在场**」的翻转结构，**止损触发点往往正是价格即将反转的那个极端点**
⇒ 止损把出场价从「MA 穿越时的收盘价」换成「被触及的极值」，**系统性卖在最低 / 买在最高**。
这也解释了为什么成交笔数几乎不变（349→351）：止损本就与自然的 MA 反转**几乎同时发生**，
并不真的"让你离场"。

### 结论

**加止损救不回来，反而更差。** 与 §四「为什么不第一轮就加止损」的预判一致，
也与 §二「信号层本身几乎无 edge」的发现自洽 —— **止损只改变亏损分布形状，不产生 edge**。

⚠️ 本实验**不改变第一轮「无效收档」的判定**；IS 样本已污染，不因此重开。

**若还要试时间止损（20 根）**：需在 `run_backtest` 新增 `time_stop_bars` 能力，
属**独立单变量**，可另跑一次；但先验同样不乐观（同一机制：时间止损也会把
"等 MA 反转"换成"到期即平"，在无 edge 的信号上只会增加成本）。
