## 二、❌ 两个不可得源：都卡在大商所

| 源 | 失败现象 | 定性 |
|---|---|---|
| `dce_receipt` | `APIError: ... 大连商品交易所网站启用了瑞数反爬虫验证 (Status code: 412)`；实测 **www.dce.com.cn 主页也 412** | **不是接口级问题，是全站 WAF 拦截非浏览器会话** |

**处置**：见 `DCE可行性结论.md`（D5，三路径 A→C→B）。当前默认走 **C：只用 SHFE / INE / CZCE / GFEX**。

## 四、PIT 可用性判断（能不能进回测，看的不是 ✅ 而是这个）

进 `np_data` 表并用于回测，必须同时满足：**① 有可真调用 ② 有可实测的公布时刻 ③ `published_at >= period_end`**。

| 源 | 可做 PIT？ | 还缺什么 |
|---|:-:|---|
| `shfe_receipt` / `czce_receipt` / `gfex_receipt` | 🟡 待实测 | 公布时刻目前是「15:00 后」的**规则描述**，不是实测上界 ⇒ 必须 `probe_sources.py --watch <date>` 打 `first_seen_at` |
| `shfe_rank` / `czce_rank` / `gfex_rank` | 🟡 待实测 | 同上；且 `shfe_rank` 还有「当日 vs T+1 发布」未定 |
| `spot_basis` | 🟡 待实测 | **采集时刻完全不明**，是全部源里前视风险最高的一类（基差直接反映价格） |
| `inv_99qh` | ❌ 否 | 只有 20 期，不够历史序列 |
| `em_inventory` | ❌ 否 | 时刻不明 + 口径不符 |
| `dce_*` | ❌ 否 | 数据取不到 |

**一句话**：11 个源里，**没有一个是「已具备 PIT 可用性」的**。全部 ✅ 都停在「能拿到数据」，还差 `--watch` 实测公布时刻这一步。这是 D6/D7 的前置。

## 六、操作坑（来自 `np_source.note`，都是实测踩过的，接管道时逐条对照）

| 源 | 坑 |
|---|---|
| `gfex_receipt` | **公共包装函数已坏**，必须走 `get_gfex_receipt(date, vars_list=["SI","LC","PS"])` |
| `czce_receipt` | **2025-11-01 起格式 xls→xlsx**，函数内已按日期分支；自己写抓取要注意这个切换点 |
| `shfe_receipt` | 返回 `dict[品种名 -> DataFrame]`，含 INE 5 项（原油 / 低硫 / 20 号胶 / BC 铜） |
| `shfe_rank` | 返回 `dict[合约 -> DataFrame]`，含成交量 / 持买单量 / 持卖单量**前 20 名** |
| `czce_rank` | akshare 自报数据源起始 20151008（实测最早 20160104） |
| `inv_99qh` | **akshare 版不带 UA 已死**，只能 requests 直读页面 `__NEXT_DATA__`；翻页 centerapi 412 |

**注①（2026-10-20 修正，实测推翻原写"含 GFEX"）**：82 个品种里广期所 5 个（LC 碳酸锂 / SI 工业硅 /
PS 多晶硅 / PT 铂 / PD 钯）的 `total` 实测为 **0**，是真无数据，不是解析失败。⇒ 覆盖只有 **SHFE+CZCE+DCE 三所**。

**注②（2026-10-20 新增取数方式）**：页面 URL 上的 `?productId=` **不生效**（SSR 永远渲染默认品种螺纹钢），
必须走 Next.js 数据路由 `/_next/data/{buildId}/data/stockIn.json?productId=N` 才能换品种。
`buildId` 每次站点部署都会变，过期返回 `404 + text/html`（不是 JSON）。82 品种 ⇒ 83 次请求 ≈ 60s。
| `spot_basis` | ★ `dominant_contract` 是**第三方主力定义**，直接拿它 join = **第二类未来函数**；必须走项目自己的换月序列 |
| `em_inventory` | 库存 ≠ 仓单（R6），且时刻不明 ⇒ **只记录不采用** |
