> 建于 2026-10-12。目的：**用最小成本把「程序化交易链路」跑通**。

## 五、★ 实测记录（2026-10-12 晚，SimNow · 全部跑通）

**最终结果**：行情 60 个合约订阅全成功、真实行情正常；交易链路
认证 → 登录 → 结算单确认 → 查资金（权益 2000 万）→ 查持仓 → **报单 → 委托回报 → 撤单 → 状态=5（已撤单）** 全通。

### 踩到的 6 个坑（**每一个都记下来，别再踩**）

| # | 现象 | 根因 | 解法 |
|---|---|---|---|
| 1 | `RuntimeError: can not open CFlow file in line 331 of ThostFtdcUserApiImplBase.cpp` | ★★ **CTP 的流文件目录不能用含中文的路径**。本项目路径含「天勤量化/工具/_CTP接入」 | flow 目录放到**纯 ASCII** 路径（默认用系统临时目录 `%TEMP%\ctp_flow_tqsdk`）；可用环境变量 `CTP_FLOW_DIR` 覆盖（仍须全 ASCII）。实测四种变体：空串 ✅ / 相对 ✅ / **中文绝对 ❌** / ASCII 绝对 ✅ |
| 2 | 目录不存在时同样报 CFlow | CTP 要求流文件目录**已存在** | 先 `os.makedirs` 建出 `md/`、`td/` |
| 3 | `AttributeError: 'CThostFtdcMdApi' object has no attribute 'SubscribePrivateTopic'` | 那是**交易 API** 的方法 | 行情侧只 `RegisterFront` + `RegisterSpi` + `Init` |
| 4 | `TypeError: list must contain strings` | SWIG 的 `char *[]` 需要 **bytes** | `SubscribeMarketData([s.encode('ascii') for s in insts], n)` |
| 5 | ★ **交易登录 `ErrorID=4 CTP:用户不活跃`** | **账号填错了** —— 用「用户账号 A…」登交易会被判不活跃；**必须用「6 位投资者代码」** | `USER_ID = "275711"`（行情登录两个账号都能用，**只有交易侧卡这个**）|
| 6 | ★★ **一次下单测试报了约 50 单** | `OnRspQryDepthMarketData` 是**每行回调一次**（查询回一大片合约），旧代码在每行都下单；靠柜台「不允许重复报单」才没成交 | 加 `_order_placed` 一次性闸门；且**必须按 `InstrumentID` 匹配**再取涨跌停价（否则会拿到别的合约的价格，曾出现「rb2611 跌停价 = 0.5」）|

### 另外一个"看起来像坏了、其实没错"的点
- **`os._exit()` 会掐断整个进程**：带 `--td` 时，行情侧收够 `--quotes` 就退出会把交易链路一起杀掉
  （表现为「td 只走到发送登录就没下文」）。已改为：带 `--td` 时行情侧不自退。
- **撤单应答 `ErrorID=26 报单已全成交或已撤销，不能再撤`** 是**正常**的 ——
  `OnRtnOrder` 会为同一笔委托多次回调；第一次撤单成功后第二次自然报这个。
- `持仓 rb2611 2 0 手` 是**零持仓记录**（CTP 有时会返回 Position=0 的行），不是有仓位。

### 推荐的首跑顺序
```bash
python 工具/_CTP接入/simnow_最小接入.py                      # 1) 只连行情
python 工具/_CTP接入/simnow_最小接入.py --env 1 --td           # 2) 加交易链路（只读查资金/持仓）
python 工具/_CTP接入/simnow_最小接入.py --env 1 --td --order --yes-i-know --inst rb2701   # 3) 下单往返
```
> ⚠️ 第 3 步**指定当前活跃主力合约**（如 `rb2701`）；用远月合约可能拿不到有效涨跌停价，
> 脚本会打印警告并**跳过**下单（这是有意设计：宁可不测，不发一个价格无意义的单）。

## 六、★ 安全设计（按项目血泪条款：会下单的脚本曾真单两次）

1. **默认不下单**——不加 `--order` 永远不会报单。
2. **`--order` 必须再加 `--yes-i-know`**，否则直接 `SystemExit`。
3. **★ 前置地址白名单**：脚本里写死 `ALLOWED_HOSTS = ("182.254.243.31",)`，
   任何前置一旦不命中就**拒绝连接**。
   ⇒ **参数怎么填都不可能误连到你的实盘期货公司。**
4. 下单测试用的是「**跌停价挂买入**」（绝不会立即成交）+ **立刻撤单**。
5. 已验证：密码为空 → 明确报错退出；`--order` 无二次确认 → 拒绝执行。

## 七、⚠️ 连不上怎么排查

| 现象 | 排查 |
|---|---|
| 完全没反应 | ① 换 `--env 1`；② 换备用前置分组；③ 确认不在 SimNow 维护窗口 |
| 登录报「用户名不存在」 | `USER_ID` 换成另一个候选：**用户账号**（A 开头）↔ **投资者代码**（纯数字） |
| 登录报认证失败 | `AppID`/`AuthCode` 是否被改过（SimNow 是固定公开值） |
| 订阅不到行情 | 合约代码是否在当前挂牌（**CZCE 是 3 位码**，如 `MA601` 而不是 `MA2601`） |
| 交易前置连上但登录失败 | SimNow 的 724 环境**不提供结算**；`--td` 建议用 `--env 1` |

## 八、⚠️ 合规：程序化交易有硬性报备要求

**《期货市场程序化交易管理规定(试行)》**（证监会〔2025〕12号，**2025-10-09 施行**）：

- **第 8 条「先报告后交易」**：交易者从事程序化交易前，须**向期货公司报告** →
  期货公司核查后报交易所 → **客户收到确认后**方可从事程序化交易。
- 第 7 条：须与期货公司签订《**程序化交易委托协议**》（中期协制定必备条款）。
- 第 10 条：须报告账户基本信息、**交易软件名称 / 基本功能 / 开发主体** ⇒ 自研软件如实报"本人自研"。
- 第 16 条：接入前期货公司须**测试客户技术系统**，测试记录保存 **≥20 年**。
- ★ **第 22 条**「建立内控/风险管理/合规管理制度」**只约束法人及非法人组织** ⇒ **个人（自然人）做程序化是允许的**。
- ⚠️ 若被认定为**高频交易**，还需额外报告：策略类型及主要内容、最高报撤单频率、
  单日最高报撤单笔数、服务器所在地、技术系统测试报告、应急方案、风险控制措施。

## 十、tick 落盘（Parquet + DuckDB）—— 已在 SimNow 实测跑通

### 为什么不用数据库
CTP 行情是**快照**（≈500ms 一笔，约 2 笔/秒），不是逐笔成交。按此估算：
单合约 ≈ 2.9~4.1 万条/日 ⇒ **行存数据库（Supabase / Postgres / MySQL）完全不适合**
（免费额度 500MB 一天就爆、云上传带宽是瓶颈、按时间范围扫亿级行效率远低于列存）。
⇒ **Parquet 分区文件 + DuckDB**：文件即数据库，不用导入、不用起服务、`SELECT` 直接查。

### 落盘结构
```
工具/_CTP接入/tick/date=2026-10-12/sym=cu2612/part-20261012-235000-00000.parquet
```
Hive 风格分区（`date=` / `sym=`），DuckDB 会自动识别成两个分区列；已加入 `.gitignore`（数据不入库）。

### ★ 实测数字（2026-10-12 23:50~23:55，SimNow 环境1，13 个有色/贵金属合约）

| 指标 | 实测 |
|---|---|
| 条数 | 5,534 条 / 5 分钟 |
| 单合约速率 | **~5,095 条/小时（1.42 条/秒）** —— CTP 快照理论上限约 2 条/秒（本例是远月非主力）|
| 磁盘占用 | **0.29 MB**（13 文件）⇒ **53 字节/条**（zstd 压缩后）|
| 推算 | 单合约一交易日(5.75h) ≈ **1.5 MB**；**100 合约一年(250 日) ≈ 39 GB** |

⇒ 与 docs 里"100 合约 ≈ 259 GB/年（CSV）、Parquet+zstd ≈ 43 GB/年"的预估**吻合**（实测 39 GB）。
**结论：个人机完全扛得住，一块 1TB 盘能存十几年。**

### ⚠️ 落盘批大小是硬教训（实测踩到）
parquet **每个文件都有固定的元数据/footer 开销**，行数少时开销压倒数据：

| `--flush` | 每文件行数 | 字节/条 | 同批数据体积 |
|---|---:|---:|---:|
| 40 秒 | ~55 行 | **348 B** ← 比未压缩 CSV 还大 | 0.76 MB |
| 300 秒 | ~426 行 | **53 B** | **0.29 MB** |

⇒ **`--flush` 别为了"实时可见"调小**；tick 落盘不需要秒级可见，默认 300 秒。
（脚本会在字节/条 > 150 时主动警告。）

### ⚠️ 两个必须处理的 CTP 细节（否则数据静默被污染）
1. **空价 = `DBL_MAX`（≈1.797e308），不是 0/NaN。**
   不处理就会把「无买一」写成天文数字，污染所有分位数/价差统计。
   本录制器统一转 NaN（`tick查询.py` 里 `无买一占比%`/`last为空占比%` 可验证）。
2. **时间戳要用 `ActionDay`（自然日）拼，不能用 `TradingDay`。**
   夜盘 23:00 的行情，`TradingDay` 已经是"明天" ⇒ 拼出来会**错位一天**。

### 用法
```bash
# 录 5 分钟（默认 724 环境、自动生成活跃合约）
python 工具/_CTP接入/tick录制.py --minutes 5

# 指定合约、录 30 分钟
python 工具/_CTP接入/tick录制.py --env 1 --minutes 30 --inst rb2701,m2701,cu2612

# 一直录（Ctrl+C 收尾并出报告）
```

### ⚠️ 关于优先序（别把顺序搞反）
**tick 不产生 edge，它只降低成本（滑点）与支持微观结构研究。**
而本项目 06 的**毛利只有成本的 4.5%** ⇒ 成本砍半仍然深负。
且 tick 级研究还要**重写现在的 bar 级撮合层**（排队/部分成交）。
⇒ **优先序：先找到有毛利的信号 > 再谈成本 > 最后才 tick。**
本录制器是把**工程管线提前铺好**（求职资产 + 将来真要用时不返工），不是主线突破口。
