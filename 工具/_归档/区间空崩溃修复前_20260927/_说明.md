# 区间空崩溃修复前_20260927 —— lib/engine.py 补丁前原件

## 修的是什么

**用户视角**：跑 生猪 / 纯碱 / 苯乙烯 的练习区间（2016-01-01 ~ 2019-12-31），
黑窗口甩一坨 traceback，最后一行是

```
UnboundLocalError: cannot access local variable '_open_blocked' where it is not associated with a value
```

既没有报告，也**看不出真正的原因**。

**真因**（已实测复现）：

1. 这三个品种在 2016 年**都还没上市**（实际最早行情：纯碱 2019-12-05、
   苯乙烯 2019-09-25、生猪 2021-01-07）⇒ 该区间一根 K 线都没有；
2. tqsdk 于是在初始化阶段（`api.get_quote()` 内部那次等待）就抛 `BacktestFinished`；
3. 这个异常被 5 个回测函数末尾的 `except BacktestFinished:` 接住；
4. 但那个处理块要打印诊断计数器 `_open_blocked` / `_gate_blocked` / `_fs_skipped`，
   而它们是在 `try` 体内、**异常发生点之后**才赋值的 ⇒ 抛 `UnboundLocalError`，
   把「这段区间没行情」这个真因整个盖掉。

## 改成了什么

两处，都在 `lib/engine.py` 的 5 个回测函数
（`run_backtest` / `run_backtest_boll` / `run_backtest_align` /
`run_backtest_swing` / `run_backtest_pro`）里：

| # | 位置 | 做什么 |
|---|---|---|
| 一 | 第一次 `api.wait_update()` 处 | `_首根就结束()` —— 就地接住 `BacktestFinished` |
| 二 | `except BacktestFinished:` 开头 | `_K线里有没有行情()` —— 判 `klines["datetime"]` 是否全 0 |

第二道是必须的：实测发现那个 `BacktestFinished` 并不是第一次 `wait_update` 抛的，
而是在紧接着的 `api.get_quote()` **内部**抛的，第一道拦不住。

命中后打印的就是人话，还会自动查出该品种最早有行情的日期：

```
>>> 生猪 KQ.m@DCE.lh 回测 2016-01-25 ~ 2016-03-31
    [!] 这段区间 生猪 一根行情都没有 —— 该品种当时还没上市（或已退市），
        所以没有信号，也不会生成报告。这不是程序坏了。
    [生猪] 最早有行情是 2021-01-07；把样本区间改到那之后，或换一个上市更早的品种。
```
