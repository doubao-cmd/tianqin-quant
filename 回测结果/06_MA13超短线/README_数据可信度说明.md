### 发生了什么

2026-10-11 做「参数孤峰检测工具」时，顺带对账发现 **12 品种 × 3 窗 = 36 份产物
报告收益全正、逐笔收益几乎全负**，遂查根因，定位到**记账架构级 bug**：

- **权益曲线（第 274-275 行）** 在持仓时逐 bar 累加 `(close[i] − close[i−1])`，
  但**不排除开仓 bar 与平仓 bar** ⇒ 每笔多算两段边界价差
  （`(close[开仓bar] − open[开仓bar]) + (出场价 − close[平仓bar])`）。
- 该误差**每笔都有**，在与持仓方向相关的行情里系统性偏向盈利侧。
- 独立复现（甲醇 2021，913 笔）：**路径① +173.13% vs 路径② −67.86%，误差占收益 139.2%**。

另有一处连带问题：**逐笔 pnl 只扣平仓单边成本**，开仓成本另走 `equity -= oc`，
使「逐笔合计 ≠ 权益变动」永久存在。

### 已做的修复

| 修复项 | 内容 |
|---|---|
| 权益口径 | `equity` 只在平仓时结算 pnl（含**双边**成本）；另存 `eq_mark` 供画图/回撤/夏普 |
| 逐笔口径 | `pnl = 价差 − 开仓成本 − 平仓成本` ⇒ **Σpnl ≡ Δequity 成为恒等式** |
| **自动对账断言** | `if abs(equity − INIT − Σpnl) > _tol: raise`（`_tol` 随笔数缩放，容纳 2 位小数舍入） |
| 产物命名 | 「开发窗」不再硬编码，改为按起止年份自动推断（否则三段互相覆盖） |
| txt 精度 | 逐笔 pnl 由 `:.0f` 改为 `:.2f`（原来取整会使 Σtxt ≠ json） |

## 二、为什么全部作废：止损价 bug

2026-10-08 的 commit `a61c3ae` 修了一处 bug：当跳空低开时，
`max(entry − 2×ATR, swing_low − 0.5×ATR)` 会选中 `swing_low` 支，
使**止损价落到入场价的有利侧** ⇒ 下一根 K 线的 `low ≤ stop` 立刻成立
⇒ 以一个**不存在的价格**平仓，凭空产生盈利。

**逐笔统计证据**（焦煤开发窗 3317 笔，本目录下的 txt）：

| 出场方式 | 笔数 | "盈利"笔 | 胜率 |
|---|---:|---:|---:|
| 时间止损 | 800 | 721 | 90.1% |
| **止损** | 2517 | **845** | **33.6%** ← 止损单不可能盈利 |

修复后同代码重跑：`止损组 0/1773 = 0.00%`（硬校验通过）。

⚠️★ **硬校验规则：止损组胜率必须恒为 0.0%。见到非 0 ⇒ 这份产物作废。**

### ★② 发现并修掉一个 bug：`cost_assumption` 标签是硬编码的

原代码把口径描述写死成「手数=当前权益×1%」（=复利），
但 `COMPOUND=False` 时实际手数基数是**锁死 20 万**。
⇒ **跑的是锁死 20 万，标签却写复利。**

**为什么这条最阴险**：它不报错，只让**下一个读这份 json 的人（或未来的我）**
以为跑的是复利。而本文档的「第 1 关校验」恰恰就是「看 `cost_assumption`」
⇒ **校验工具本身被污染了。**

取证：跑完 12 品种后逐份读 `cost_assumption`，24 份里有 12 份写着「当前权益×1%」，
而同批产物的 `final_equity` 全部对应锁死 20 万的曲线。

修法：标签改由两个开关动态生成，并留标定日期（补丁 `工具/_输出/_修标签硬编码_20261010.py`）：

```
手数=锁死200000(对齐模拟盘RISK_EQUITY)×1%÷ATR风险夹[1,8]+名义敞口≤权益×2倍;
止损=GAP_FILL保守成交(多头min(止损线,开盘)/空头max); ... ; 标定2026-10-10
```

修完重跑焦煤验证：**指标一字未变**（2801 / 31.95% / 5.291 / +899.89%）
⇒ 证明只改标签未动逻辑。四种开关组合渲染出四种互不相同的标签。

⇒ ★★ **纪律：任何写进产物的「口径描述」必须由代码路径生成，不能手写字符串。**
手写标签在参数一改就变成谎言，且**不产生任何报错** ——
这是比计算错误更难发现的一类 bug，因为它让校验工具失去校验能力。
