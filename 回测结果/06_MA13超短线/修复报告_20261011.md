## 一、罪魁祸首：一句话结论

> **罪魁祸首是一行代码：`equity += pos * (close[i] - close[i - 1]) * MULT`。**

它出现在 `策略/06_MA13超短线/回测/<品种>/MA13超短线_回测.py` 第 274-275 行
（原文件行号），在**每个 bar 循环末尾**执行。

```python
        if pos != 0:
            equity += pos * (close[i] - close[i - 1]) * MULT   # ← 罪魁祸首
        peak = max(peak, equity)
        dd = (peak - equity) / peak if peak > 0 else 0.0
        bar_dds.append(dd)
        eq_series.append(equity)
        ...
        total_return = (equity - INIT) / INIT   # 报告里的收益就取自这里
```

## 二、为什么这一行是错的（源码级推演）

### 2.1 两套账并存，但只有一套是对的

同一个策略脚本里，**盈亏被记了两遍，用了两套互不相容的口径**：

| 路径 | 代码 | 用途 | 对不对 |
|---|---|---|---|
| **① 逐笔记账** | `pnl = pos * (exit_price - entry_price) * MULT - exit_cost` | 写进 `.txt` 逐笔明细 | 基本对（但只扣单边成本） |
| **② 权益曲线** | `equity += pos * (close[i] - close[i-1]) * MULT` | 画权益图、算**收益率/夏普/回撤** | ❌ **错** |

**报告里的所有数字（`total_return` / `sharpe` / `max_drawdown`）全部来自路径②。**

### 2.2 路径②错在哪：`if` 没排除开仓/平仓 bar

路径②的假设是：「持仓期间的权益变化 = 每根 bar 的收盘价差 × 手数 × 乘数」。
**这个假设在「持仓中间」成立，但在开仓那一根和落平仓那一根不成立。**

```
时间轴（5 分钟 bar）：
        bar p（开仓）      bar p+1 ... bar q-1      bar q（平仓）
        ┌──────────┐      ┌─────────────┐         ┌──────────┐
价格    open[p]           close 逐根走           open[q]=出场价
        │  ↑ 真实起点                    ↑ 真实终点 │
        └──────────────────────────────────────────┘
         真实盈亏区段 = open[p] → open[q]

路径②实算的区段 = close[p] → close[q]（还多算了 p 和 q 两根的 bar 内价差）
                   ↑ 起点错            ↑ 终点错
```

**误差 = 每笔交易多算两段：**

```
Δ = Σ s · hand · MULT · [ (close[开仓bar] − open[开仓bar])
                        + (出场价   − close[平仓bar]) ]
```

- **第一段 `close[p] − open[p]`**：`pos` 在开仓那一 bar 已置位，
  于是把「开仓后到收盘」这段走势也当成了持仓盈亏；
- **第二段 `出场价 − close[q]`**：`pos` 在平仓那一 bar 还没清零，
  于是又算了「从收盘到出场」这段（出场发生在 `open[q]` 或止损价）。

### 2.3 为什么它「看起来像赚钱」

这两段误差**单独看是随机的**（有正有负），但：
- 策略是**顺势**的（趋势方向开仓）；
- 开仓后的那一 bar，价格**大概率延续持仓方向**（这正是回踩确认的机制）；
- 于是第一段 `close[p] − open[p]` **大概率与持仓方向同号** ⇒ 系统性偏向盈利。

⇒ **每笔交易被凭空塞进一段「顺向的 bar 内涨跌」，几千笔累加，滚成天文数字。**

## 四、次级 bug：逐笔 pnl 只扣单边成本

修第一处时，**新加的对账断言立刻抓出了第二个问题**：

```
[FATAL] 对账失败: equity=462.00 INIT=200000.00 sum(pnl)=-58466.00 diff=-141072.00
```

差额 141,072 ≈ 全部交易的**开仓成本之和**。原因是：

| 成本 | 旧代码在哪扣 | 结果 |
|---|---|---|
| 平仓成本 `exit_cost` | `pnl = ... - exit_cost` 里扣 | ✅ 进了逐笔 |
| **开仓成本 `oc`** | `equity -= oc` 单独扣 | ❌ **没进逐笔** |

⇒ 逐笔 pnl 合计 **永远不等于** 权益变化 —— 两套账从根上就对不上。
**这意味着：即使路径②改对了，只要不修这里，对账断言仍然会一直失败。**

**修法**：`pnl = 价差 − 开仓成本 − 平仓成本`（双边），开仓时不再即时扣。
现在 **`Σpnl ≡ Δequity` 成为恒等式**，可被断言永久锁死。

## 五、改了哪些内容（完整清单）

### 5.1 策略核心改动（12 个脚本，字节级一致，仅 `SYMBOL_KEY` 不同）

| # | 改哪里 | 改前 | 改后 |
|---|---|---|---|
| 1 | **权益记账** | `equity += pos*(close[i]-close[i-1])*MULT`（逐 bar 累加） | `equity += pnl`（**只在平仓时**） |

| 6 | **★ 对账断言** | 无 | `if abs(equity − INIT − Σpnl) > _tol: raise` |
| 7 | **窗口名** | 硬编码「开发窗」 | `_window_name()` 按年份自动推断 |
| 8 | **窗口可覆盖** | 写死 | 支持 `MA13_START` / `MA13_END` 环境变量 |
| 9 | **txt 精度** | `{pnl:.0f}`（取整） | `{pnl:.2f}`（与 json 一致） |

改动量：**12 文件，867 行新增、193 行删除**。

### 5.2 关键代码（修复后）

```python
# ── 开仓：只记成本，不动 equity ──
cur_open_cost = oc
eq_mark = equity

# ── 平仓：一次性结算（含双边成本）──
exit_cost = SLIP * TICK * MULT * abs(pos) + COMM * abs(pos)
pnl = pos * (exit_price - entry_price) * MULT - cur_open_cost - exit_cost
equity += pnl
eq_mark = equity
cur_open_cost = 0.0

# ── 逐 bar：仅更新绘图镜像，不碰 equity ──
if pos != 0:
    eq_mark = equity + pos * (close[i] - cur_entry_price) * MULT
else:
    eq_mark = equity

# ── 循环结束后：对账断言 ──
_pnl_sum = sum(r["pnl"] for r in trades_rec)
_diff = equity - INIT - _pnl_sum
_tol = max(1.0, len(trades_rec) * 0.01)
if abs(_diff) > _tol:
    raise AssertionError("记账对账失败：已实现权益 != INIT + 逐笔 pnl 合计")
```

## 八、为什么这个 bug 能活两个月（方法论教训）

1. **两套账并存且从未被强制对齐** —— 信号逻辑与报告逻辑用了不同的盈亏定义，
   而没有任何一步比较它们。
2. **数字太好看时没有停下来质疑** ——「20 万本金、8 手封顶、回撤 7%、收益 +900%」
   这组数本身就该被怀疑（README 问题 3 里我甚至写过「这个组合本身可疑」，
   **但只是写下来，没有去查**）。
3. **写下来 ≠ 查清楚。** 记录疑点不等于排除疑点。
4. **这次能发现，是副产品式的检查** —— 我本来要做「参数孤峰检测工具」，
   顺手做了个「报告 vs 逐笔」对账才撞见。**正面检查漏掉的东西，侧面检查常常能捞到。**
5. **对账断言是最有价值的产出** —— 它不是「这次修好了」，而是
   「**以后不可能再犯**」。没有它，换个人、换台机器、换个复制粘贴，同样会重演。

### 9.3 carry 为什么是无辜的（关键区分）

`路线二_carry` 的 `equity += pos * (spread - prev_spread) * MULT * LOTS` **表面同形**，
但它：

- **逐日循环**（`if day == last_day: continue`，一天只处理一次），**不是逐 bar**；
- `prev_spread` = **昨日收盘价差**，`spread - prev_spread` = 持仓**一整天**的真实盈亏；
- 没有「同一 bar 内开仓+平仓」的可能 ⇒ **边界误差不存在**。

**独立数学验证**（构造 18 个价差、模拟翻转）：逐日累加 vs 逐笔开平仓，
**期末差额 = 0.00** ⇒ 两者等价。

⇒ 佐证：carry 的产物本就是**负的**（−10% ~ −21%）；若真有 MA13 那个 bug，
顺势策略会显示天文正收益。**横向对比一眼就分出来。**

### 9.4 教训（已写进 README §七问题 19.9）

> `grep` 同形模式只能**定位候选**，不能**断定 bug**。
> **必须读该文件的循环粒度（逐 bar vs 逐日）与开平仓时序。**

这是项目铁律「**判某个判据是不是 bug，必须回源码读它自己的实现**」的又一次实证
（上一次是 2026-10-08：`grep "want > 0"` 8 处只有 1 处是真 bug）。
