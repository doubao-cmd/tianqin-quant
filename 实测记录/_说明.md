## 两类记录器（互补，互不替代）

| | **策略视角**（模拟盘脚本内部写） | **账户视角** `AccountLedger` |
|---|---|---|
| 回答 | 这个策略发了什么信号、下了什么单 | 账户里真实成交了什么（像期货软件） |
| 位置 | `实测记录/<策略>/<品种>/` | `实测记录/账户/` |
| 文件 | `<品种>_成交流水.csv`、`<品种>_运行心跳.csv` | `成交明细.csv`、`账户快照.csv`、`流水单事件.log` |
| 用途 | **台账工具依赖它**（判断程序有没有在跑） | 执行质量核对：滑点 / 手续费 / 拒单 / 漏单 / 浮盈 |
| 覆盖 | 单策略单品种 | **账户内所有品种、所有策略，一份文件** |

账户流水单由 `lib/account_ledger.py` 实现，已接入全部 `run_live_*` 函数；
在模拟盘入口脚本里传 `LEDGER_DIR = os.path.join(_ROOT, "实测记录", "账户")` 即可开启
（**2026-09-27 起 60 个入口全部传了**）。

## 为什么要「心跳」这一层

回测有报告，模拟盘以前什么都没有。而模拟盘要解决一个回测解决不了的问题 ——
「这段时间没交易，到底是**程序没开**，还是**程序开着但条件不够**？」

5 个 `run_live_*` 函数每 5 分钟往 CSV 写一行「运行心跳」，**休市照写**。于是：

- 心跳出现**时间断层** ⇒ 只可能是**程序当时没在跑**（停机 / 关机 / 崩溃）
- 心跳**连续**却没有 `SIGNAL` 行 ⇒ **程序在跑、条件不够**

两者由此完全分开。再加一条判据分辨「停机有没有代价」：断层前后的 K 线时间若
**未推进** ⇒ 当时根本没有新 K 线收盘 ⇒ **不会漏信号**；推进了 ⇒ 可能漏掉信号（台账会标出来）。
