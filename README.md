## 一、这个系统在解决什么问题

做策略研究时，真正花时间的从来不是「想出一个指标」，而是**让策略从研究代码
安全地活到实盘，且能证明它没有偷看未来**。本仓库围绕这一条主线构建：

```
想法 → 回测（样本内） → 样本外验证 → 模拟盘 → 云端实盘 → 台账对账 → 异常熔断
         ↑                                              │
         └──────────── 样本外只跑一次，绝不回头调参 ────┘
```

### 核心设计原则（写死在项目里，不可绕过）

| 原则 | 落地方式 |
|---|---|
| **禁未来函数** | 信号只用已收盘 K 线，成交价取**下一根开盘价**；禁用 ZigZag 等重绘指标 |
| **先有逻辑再写代码** | 不为提高胜率叠加过滤条件、不扫描参数择优、不做单品种专属标定 |
| **样本内外分离** | IS / 验证 / 期末考三段隔离，样本外只跑一次，**看过即污染** |
| **单变量迭代** | 每次只改一处逻辑，改完立即回测记录，便于归因 |
| **风控独立于策略** | 账户级回撤熔断 + 会话异常重启，与信号逻辑解耦 |

这四条是**项目级铁律**，不是建议。代码里有多处在注释中标注了对应的踩坑记录。

### 引擎接口

`lib/engine.py` 提供 5 套策略的回测与实盘入口，签名对称（`run_backtest_X` / `run_live_X`）：

| 策略 | 回测入口 | 实盘入口 |
|---|---|---|

| 通用均线 | `run_backtest` | `run_live` |
| Pro 增强 | `run_backtest_pro` | `run_live_pro` |

每手保证金按 `信号根收盘价 × 乘数 × 保证金率` 动态计算，并随权益缩水自动收紧。

## 三、风控与稳定性防护

这部分是本仓库投入精力最多的地方——**因为它解决的是「策略会死」而不是「策略赚不赚」**。

| 防护 | 触发条件 | 动作 |
|---|---|---|
| 账户回撤熔断 | 权益回撤达阈值（默认 20%） | **闩死** + 跨会话持久化，重启不自动复位 |
| 会话异常重启 | 引擎主循环异常退出 | 整体重启会话（而非原地重连） |
| 核心单实例锁 | 检测到已有核心进程 | 拒绝启动，防止双份下单 |
| 止损线丢失补挂 | 启动/重连后持仓无止损 | 用统一公式重算止损线 |
| 滑点/成交偏离统计 | 每笔成交后 | 记录决策价 vs 云端成交均价差 |
| 运行前代码快照 | 每次启动 | 归档代码版本，可追溯 |

### 两个值得说明的设计决策

**1）熔断用「重启整个入口」而不是「原地重连」**

引擎每次启动会自建 7 个 serials（行情/账户/持仓各一路）。断线后原地重连，
只要漏掉一路重连，该路就静默失效——表现为「持仓裸奔且无人察觉」。
因此宁可整体重启，也不做原地重连。

**2）回撤熔断必须闩死 + 持久化**

如果熔断只在内存里，重启就自动复位 ⇒ 相当于没有熔断。
本项目把熔断状态落盘，重启后仍保持闩死，需人工确认才解除。

## 四、研究方法论

### 样本区间（三段隔离）

| 区间 | 时段 | 用途 |
|---|---|---|
| 样本内 IS | 2016-01-01 ~ 2019-12-31 | 逻辑开发与检验 |
| 验证 | 2020-01-01 ~ 2024-12-31 | 跨年矩阵、稳健性检验 |
| 期末考 | 2025-01-01 ~ 2026-09-30 | 最终验证，**只跑一次** |

> 上市较晚的品种（纯碱 / 苯乙烯 / 生猪）练习区间单独后移，横向对比时需注意。

### 前向诊断工具

`工具/MA13前向诊断.py` 是**只读诊断**工具：不改策略、不下单、不调参，
只回答一个问题——**信号发出后若不止损，价格是先走对还是先走错**。

- 「先走对」比例 ≈ 50% ⇒ 信号本身无 edge，换出场规则无用
- 显著 > 50% ⇒ 信号有 edge，利润是被出场规则切掉的

这个工具存在的意义是：**用数据替代猜测**，避免在无 edge 的逻辑上反复调参。

### 本地自检

防护层代码均配有离线自检脚本，不依赖网络即可验证：
- `工具/自检_回撤熔断_20261008.py`（32 项）
- `工具/自检_会话重启_20261008.py`（13 项）
- `工具/环境自检.py`、`工具/模拟盘自检.py`（48 个入口）

## 五、技术栈与运行

### 依赖

Python ≥ 3.9（实测基准 3.12.1 / Windows 10）。第三方依赖**只有 3 个**，全部由 [tqsdk](https://github.com/shinnytech/tqsdk-python) 生态提供：

```
tqsdk >= 3.10.2      # 行情 / 历史数据 / 回测 / 模拟交易 / 实盘交易
pandas >= 1.1.0      # 回测指标、台账聚合、回撤统计
numpy  >= 1.20.0     # 指标向量化
```

```bash
# 方式一（推荐，日常开发）
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt

# 方式二（需要完全复现实测环境时）
pip install -r requirements.lock.txt
```

> `requirements.txt` 只声明**直接依赖**（实测扫描全仓库 13 个 `.py` 文件得出），
> tqsdk 的 14 个传递依赖交给 pip 自动解析，手工钉版本反而容易和它的约束打架。
> `requirements.lock.txt` 是本机 32 个包的**精确快照**，用于换机复现。

其他说明：
- **不需要 TA-Lib**：技术指标全部自行实现（只用 pandas/numpy），避免指标库版本差异造成口径漂移。
- **不需要 vnpy**：本项目直接用 tqsdk，不走 vnpy 生态。
- **Windows 若卡在编译依赖**：改用 tqsdk 官方 exe 安装包，见[官方安装说明](https://doc.shinnytech.com/tqsdk/latest/installation.html)。

### 1. 出场与开仓在同一根 K 内相邻执行（无冷却期）

if pos > 0 and (l <= s["stop"] or s["bars_in"] >= MAX_HOLD):

# 紧接着往下走

    ...                               # ← 此时 pos 已是 0，允许立即重开
```

**后果**：当一根 K 线同时满足「时间止损到期」与「回踩信号成立」时，

10:50:00  多平 8 手 @3740   时间止损=True   持仓期浮盈 +1520
10:50:00  多开 8 手 @3740   ← 同价位同方向立即重进
```

**当前状态**：**未修复，且是刻意的**。

- 同时也没有证据说明加冷却期能改善结果（样本不足）。

**为什么仍然写在这里**：这是一个**已确认存在、但主动不修**的行为。
把它记下来，比藏起来更有价值——它让「为什么不修」这个决策本身可被审查。

### 2. 两类出场的性质截然不同（16 笔样本，2026-10-09 12:04 统计）

按出场原因把 16 笔拆开，盈亏分布是**反向**的：

| 出场方式 | 笔数 | 合计盈亏 | 平均每笔 | 判读 |
|---|---:|---:|---:|---|
| **时间止损** | 3 | **+9,440 元** | **+3,147** | 持仓期间有实质浮盈，被时限砍掉 |
| 价格止损 | 13 | **−17,620 元** | −1,355 | 开仓几乎立刻反向，**开仓即错** |

极端案例：棕榈油 10-09 多开 9638 → 时间止损平 9743，**单笔 +8,400 元**，
占全部正收益的 89%；而价格止损 13 笔每笔都在 −1,000 ~ −4,000 之间。

⇒ 结论：两类出场是**两个不同的问题**——
- 价格止损（13 笔，−17,620）指向「**入场逻辑在震荡市无 edge**」＝主要矛盾；
- 时间止损（3 笔，+9,440）指向「`MAX_HOLD=15` 可能偏短」＝次要矛盾。

⚠️ **但这里有一个统计陷阱，必须说破**：时间止损的 3 笔是**盈利被截断**，
价格止损的 13 笔是**亏损被截断**。两组不是同类样本，
直接比均值会高估「时间止损」的价值——真实情况是：
**如果放开 MAX_HOLD，13 笔价格止损里有多少会变成盈利，目前无法回答**，
因为它们在触及止损前从未被允许继续持有。

**按规则 4（每次只改一处逻辑），本项目不同时动这两处** ⇒ 先继续累积样本。

### 6. ★★ 三个出场改造全部失败，暴露了策略的真实收益结构

> ⚠️ **2026-10-11 补注**：本节所有数字出自**修复前的失真记账口径**

> 但下面**方向2 的失败模式**（出场与进场自相矛盾、1.5 根 bar 就退出）是
> **结构性的、与记账无关**，该结论仍成立。

2026-10-09 在 `2025-03~2026-03` 窗口（锁死20 万口径）跑了三个方向，
**三个全部让收益崩塌**。这一节的价值不在于「失败了」，
而在于**失败的方式一致，因而定位到了根因**。

| 方向 | 改动 | 等权夏普 | 正夏普品种 |
|---|---|---:|---:|
| 原版（对照） | — | **1.593** | **4/5** |
| 方向1 | 加止盈（涨/跌满 2×ATR 平仓） | −4.036 | 0/5 |
| 方向2 | 回踩 MA13 平仓 | −2.447 | 1/5 |
| 方向3 | 周期 5min → 1min | −0.878 | 2/5 |

**方向2 的失败模式最干净**，值得单独看：

| 出场方式 | 笔数 | 占比 |
|---|---:|---:|
| **回踩均线平仓** | 874 | **75%** |
| 止损 | 237 | 20% |
| 时间止损 | 48 | 4% |

根因：**进场条件本身就是「回踩 MA13」**
（`touch = abs(close[i-1] - ma13[i-1]) <= 0.5 × ATR`）。
于是持仓后价格只要再次碰到 MA13 就立刻平仓——**开仓后约 1.5 根 bar 就退出**。
出场逻辑与进场逻辑**自相矛盾**，时间止损占比从 37% 崩到 4%。

**方向1（止盈）则是另一种失败**：它把时间止损从 341 笔压到 11 笔，
全都改由止损出场（218 笔，均值 −1,653）。趋势没走完就被 2×ATR 截断，
每次只赚 1,200 出头，还要付手续费和滑点。**四腿爆仓**。

⇒ **根因（三个方向共同指向）**：MA13 的收益结构是
**「小止损 + 让利润跑」**（原版时间止损占 37%，止盈组 100% 盈利、均值 +1,214）。
**任何把出场提前、砍短的改动都会崩。**
⇒ 这也是**为什么后续不再往出场里加条件**（规则 2：不叠加过滤）。

⚠️ **注意这不构成「参数没调好」**：方向2 即便调 MA13 周期也救不回来
（那就变成单品种参数标定，违反规则 2）。

### 8. ★★ 回测与模拟盘的仓位口径曾不一致（已修）

**这直接决定「回测数字能不能和模拟盘对账」。**

| | 手数计算基数 |
|---|---|
| 回测（2026-10-07 起） | `h = (当前权益 × 1%) ÷ (ATR×一跳×乘数)` = **复利** |
| 模拟盘 | `RISK_EQUITY = 200000.0` **强制**覆盖传入的账户权益 = **锁死 20 万** |

⇒ 模拟盘 `ma13_live_multi.py` 里那句注释「与回测 INIT 严格对齐」**是错的**——
回测早已改成复利。

**处置**：2026-10-09 用户拍板**方案 A —— 改回测，不动模拟盘**
（理由：锁死 20 万保住单腿收益可加性，`E[组合] = ΣwᵢE[腿ᵢ]` 成立；
且改模拟盘要重启正在跑的进程）。
实现为两个**开关**（默认即目标口径）：

```python
GAP_FILL = True     # 止损按跳空保守侧成交：多头 min(止损线, 开盘价)
COMPOUND = False    # 手数预算基数 = 固定 20 万
```

**⚠️ 开关设计是为了同时跑 4 格归因**（`工具/_输出/MA13_归因.py`）：
一次跑出「跳空 × 复利」四种组合各自贡献多少，比串行改两次更强（多拿到交互项）。

**归因结论（2021-2023 开发窗）**：

| | 复利 True | 锁 20 万 False |
|---|---:|---:|
| 理想价 False | 927.0% / 夏普 3.401 | 419.8% / 夏普 3.473 |
| 跳空 True | 927.0% / 夏普 3.401 | **419.8% / 夏普 3.473** |

- `COMPOUND` 影响巨大（927%→420%），但**回撤更小、夏普反而更高**——
  复利是靠放大仓位赌出来的，去掉它净值更平滑。
- 甲醇/鸡蛋几乎不变 ⇒ 名义敞口夹本来够用，复利只在**高波动品种**（焦煤/棕榈油）上放大收益。
- `GAP_FILL` 对**总收益数字零影响**（止损亏更多 ⇄ 提前离场少赚，恰好对冲），
  但保留它= 口径上更诚实（模拟盘实测成交价确有 ±20 点偏差）。

### 9. ★ 两次「工具报了 bug，其实是工具自己错」

写了一个体检脚本（`工具/_输出/_MA13全面体检_20261009.py`，9 项检查），
第一版报了 **3 个 P0 级问题，复核后全是假报**：

   **结论绝不直接来自正则**。
2. **判断「某个开关生效了吗」要看开关本身，不能看它影响的函数。**

⚠️ 这与本节开头「不能只看数据表象」是同一条原则——
**体检脚本自己也会有 bug，必须被同样对待。**

### 10. ★ 止损成交价的理想价假设：查了，结论是「改不改都不影响数字」

### 13. ★★★ 参数快照里的口径标签是硬编码的，会说谎（2026-10-10）

**问题**：12 个回测脚本写产物时，`cost_assumption` 字段是一个**硬编码字符串**：

```python
"cost_assumption": f"...; 手数=当前权益×{RISK_PCT*100:.0f}%÷ATR风险夹[1,8]..."
```

但 2026-10-09 我加了 `COMPOUND` 开关，当 `COMPOUND=False` 时实际手数基数是
**锁死 20 万**（对齐模拟盘）。⇒ **跑的是锁死 20 万，标签却写「当前权益×1%」=复利。**

**为什么这条最阴险**：它不产生任何报错，只会让**下一个读这份 json 的人（或未来的我）**
以为跑的是复利口径，从而做出错误判断。整个仓库的「三关校验法」（见
`回测结果/06_MA13超短线/README_数据可信度说明.md`）第一关就是「看 `cost_assumption`」——
**校验工具本身被污染了。**

**取证**：跑完 12 品种后逐份读 `cost_assumption`，发现 24 份里有 12 份标签写着
「当前权益×1%」，而同一批产物的 `final_equity` 全部对应锁死 20 万的曲线。

**修法**：标签改为由开关动态生成，两处口径都进标签，并留标定日期：

```python
"cost_assumption": (
    f"滑点{SLIP}跳+佣金{COMM}元/手/边; 本金{INIT:.0f}; "
    + (f"手数=锁死{PRINCIPAL:.0f}(对齐模拟盘RISK_EQUITY)×…"
       if not COMPOUND else f"手数=当前权益×…")
    + (f"+名义敞口≤权益×{NOTIONAL_CAP:.0f}倍; "
       + ("止损=GAP_FILL保守成交…" if GAP_FILL else "止损=理想价成交(虚高,仅供对照)"))
    + f"; 乘数{MULT}; 一跳{TICK}; 标定2026-10-10"
)
```

修完重跑焦煤验证：**指标一字未变**（2801 笔 / 31.95% / 夏普 5.291 / +899.89%），
证明只改标签未动逻辑。四种开关组合渲染出四种互不相同的标签。
补丁：`工具/_输出/_修标签硬编码_20261010.py`（幂等、支持 `--撤`、带静态校验）。

⇒ **纪律：任何写进产物的「口径描述」必须由代码路径生成，不能手写字符串。**
手写的标签在参数一改就变成谎言，而且**不会有任何报错**——
这是比计算错误更难发现的 bug 类型，因为它让校验工具失去校验能力。

### 14. ★ 仓库体积 65 MB → 2.96 MB，以及 `git rm --cached` 的三个坑（2026-10-10）

**问题**：`回测结果/` 有 178 份产物被跟踪、合计 **62.35 MB**，其中 HTML 报告 81 份
就占 56.94 MB（单份 1.9 MB，因为内嵌了 5 万根 K 线）。对求职作品集是**负资产**：
clone 慢、网页打开慢，而且**里面大半是止损夹紧修复之前的 bug 版本**，留着持续误导。

**决策**：HTML 报告与逐笔 txt 一律脱库——它们能由
`策略/<策略>/回测/<品种>/回测.bat` 随时重新生成，不是资产。
**本地文件一个没删**（仍是 228 个 / 85 MB），随时可改回来。

| | 跟踪文件 | 体积 |
|---|---:|---:|
| 脱库前 | 547 | **65.28 MB** |
| 脱库后 | 396 | **2.96 MB** |

保留入库的是 **25 份 `_参数.json`（0.02 MB）+ 2 份 .md** ——
参数 json 是**口径的证据**（`cost_assumption` 字段写明手数基数/止损成交方式/乘数/一跳），
脱库了数字就没法自证。

**踩到的三个坑**：

1. **`git rm --cached -r <目录>` 会把整个目录移出，包括想保留的。**
   正确做法：先 `rm --cached -r`，再**不带 `-f`** 地`add` 回去，让 gitignore 生效。
2. **`git add -f` 会绕过 gitignore**，会把刚排除掉的 152 份全部加回来。
   ⇒ 「强制入库单个文件」只能用 `-f` 且**指定到文件**，不能指定目录。
3. **`gitignore` 没有「例外套例外」。**
   `回测结果/_说明.md` 被 `第 103 行 _*.md` 拦住（既有规则），
   它不匹配 `*.html`/`*.txt` 也就不需要 `!` 例外，但仍然进不来
   ⇒ 最终对它单独 `git add -f`。

⇒ **纪律：改 `.gitignore` 后必须用 `check-ignore -v` 实测一条真规则和一个例外**，
不要只看规则写得对不对——本次三处坑全部是「规则对但结果不对」。

### 15. 截面持仓量因子「增仓滞涨」：两轮实验都被证伪（预注册卡已收档）

### ★★ 多张预注册卡连续无效之后，最有价值的是这五个方法论结论

**① 预注册卡冻结前必须先做「信号频率预算」。**

信号频率可以用历史数据**解析计算**（半小时），不需要先建引擎。
本次是建完全套引擎 + 29 项单元测试之后，才发现冻结参数下一个信号都没有。
今后立卡流程固定为：**定义 → 频率预算 → 冻结 → 引擎 → 单元测试 → 跑**。

**② 「零干净样本外」这件事，在天勤免费版下是数学问题，不是纪律问题。**

实测：9 个品种的主连日线 `data_length=3000`（本应回溯 ~12 年）**最早一律 2016-01-04**，
共 2613 根 ≈ 2016-01-04 至今天的全部交易日。

⇒ **能取到的数据区间，恰好等于被跑过的区间**。所以「找一段没人看过的年份」这件事，
在当前数据源下**不存在**，无论怎么调整窗口划分都没用。
同理，**展期收益（carry）在免费数据下做不严谨** —— 实测 4/4 具体合约（含当前主力 DCE.m2701）

## 七之三、★★★ 问题 19：一个让全部收益数字翻倍的记账 bug（2026-10-11）

**这是本项目至今最重要的自审记录。** 它不是策略问题，是**我在自己的回测代码里
造出了一个系统性虚高，然后拿它当证据用了两个多月**。

### 19.1 起因

原计划做一个「参数孤峰/高原检测工具」，第一步只读诊断时，顺手做了一次
「报告收益 vs 逐笔收益」对账，发现：

> **12 个品种 × 3 个窗口，共 36 份产物：报告收益为正 34 份，逐笔收益为负 35 份。**

这个矛盾太大，不可能用「策略不好」解释。于是停下来查根因，而不是继续做工具。

### 19.2 根因：两条记账路径不一致（源码级）

`策略/06_MA13超短线/回测/<品种>/MA13超短线_回测.py` 里有**两套并存的记账**：

```python
# 路径① 逐笔记账（第 225 行）—— 正确
pnl = pos * (exit_price - entry_price) * MULT - exit_cost

# 路径② 权益曲线（第 274-275 行）—— 错误
if pos != 0:
    equity += pos * (close[i] - close[i - 1]) * MULT
```

第 274 行的 `if` **不排除开仓 bar 与平仓 bar**：
- 开仓 bar `p`：`pos` 已置位 ⇒ 把 `(close[p] − open[p])` 也算进权益，
  而这笔交易的真实起点是 `open[p]`；
- 平仓 bar `q`：`pos` 尚未清零 ⇒ 又算了 `(close[q] − close[q−1])`，
  而真实出场价是 `open[q]`（或止损价）。

⇒ **边界误差** = Σ `s·hand·MULT·[(close[开仓bar] − open[开仓bar]) + (出场价 − close[平仓bar])]`

这个误差**每笔交易都有**，且方向随机——但在有趋势的市场里，它与持仓方向正相关，
于是**系统性偏向盈利侧**。

### 19.3 量化：失真有多大

`工具/_输出/_独立复现_两套记账_20261011.py`（真实行情，甲醇 2021 全年，913 笔）：

| 记账方式 | 期末权益 | 收益 | 夏普 |
|---|---:|---:|---:|
| 路径① 逐 bar close（**当时策略在用**） | 546,260 | **+173.13%** | 7.00 |
| 路径② 逐笔 open→open（**正确口径**） | 64,270 | **−67.86%** | — |
| **边界误差** | **481,990（占路径①收益 139.2%）** | | |

全部 36 份产物：报告收益合计 **+6,516%**，逐笔收益合计 **−2,973%**。

### 19.4 修复

**(a) 权益改为「已实现」口径**：`equity` 只在平仓时结算 `pnl`（含双边成本），
持仓期间另存一条 `eq_mark`（mark-to-market 镜像）仅供画图/回撤/夏普。

**(b) 逐笔 pnl 改为含双边成本**：原 pnl 只扣平仓单边成本、开仓成本另走 `equity -= oc`，
导致「逐笔合计 ≠ 权益变动」永久存在。现在 `pnl = 价差 − 开仓成本 − 平仓成本`，
**Σpnl ≡ Δequity 成为恒等式**。

**(c) ★ 加自动对账断言**（这条是本次最重要的流程补丁）：

```python
_pnl_sum = sum(r["pnl"] for r in trades_rec)
_diff = equity - INIT - _pnl_sum
_tol = max(1.0, len(trades_rec) * 0.01)   # 逐笔 pnl 保留 2 位小数的累计舍入上限
if abs(_diff) > _tol:
    raise AssertionError("记账对账失败：已实现权益 != INIT + 逐笔 pnl 合计")
```

**没有这条断言，同类 bug 一定会再犯。** 它把「账目必须自洽」从人的记忆变成了机器的强制。

**(d) 顺带修掉的**：产物命名硬编码「开发窗」（跑三段会互相覆盖）；
窗口改为支持环境变量覆盖（只切数据集，**不动策略逻辑**，不违反规则 2/4）。

### 19.5 修复后重跑：真相

| 窗口 | 正夏普品种 | 等权收益 | 等权夏普 |
|---|---|---:|---:|
| 开发窗 2021-2023 | **0/12** | −101.2% | −1.51 |
| 前向窗 2024-2025 | 2/12 | −95.7% | −1.39 |
| 探针窗 2026 | **0/12** | −69.4% | −3.25 |

**⇒ MA13 超短线没有 edge。** 之前所有 +100%~+900% 的数字，100% 由这个 bug 产生。

### 19.6 我在这次调查中的 4 个假设，前 3 个是错的

| # | 假设 | 结果 |
|---|---|---|
| 1 | 逐笔 pnl 漏记开仓成本 | ❌ 推翻：差额 1231 万 ≠ 开仓成本 302 万 |
| 2 | bar 的 open==close（伪 bar） | ❌ 推翻：实测 5min 45.4%、日线 15.2%，是真实 OHLC |
| 3 | 手数与盈亏相关致选择性偏差 | ❌ 推翻：实测相关系数 ≈ 0.017 |
| 4 | 两条记账路径口径不同（边界错配） | ✅ **成立**（独立复现证实） |

**记录这段过程本身就是方法论的一部分**：在没有独立复现之前，
任何「看起来很合理」的推断都可能是错的。这与 §9、§18 是同一条教训的第三次出现。

### 19.7 为什么会犯这个错（以及为什么它值得写进仓库）

1. **两套记账并存**是根因。策略逻辑（信号）与报告逻辑（权益）用了不同的盈亏定义，
   而两者从来没有被强制对齐过。**任何一处对不上，都会被读到报告的人当成事实。**
2. **没有断言、没有对账**。逐笔 pnl 与权益曲线都是「输出」，没有任何一步比较它们。
   一个能自我核验的系统，不该依赖「作者记得去比对」。
3. **数字太好看时，本该先怀疑**。「20 万本金、8 手封顶、回撤 7%、收益 +900%」
   这组数在任何有常识的人眼里都该先被质疑（问题 3 里我写过「这个组合本身可疑」，
   但只是写下来，没有去查）。**写下来 ≠ 查清楚。**
4. **它证明了自审机制的价值**：如果不是要做「参数孤峰检测」这个无关工具，
   这个 bug 可能还要再活很久。**副产品式的检查，常常比正面检查更早发现问题。**

### 22. 保本止损：把止损移到开仓价，5 品种等权夏普反而**恶化**（预注册卡已收档）

## 七之六、2026-10-12 深夜：用工具把「一整类进场信号」批量证伪

### 23. 进场体检：6 类价格进场信号 × 12 品种 = 72 组，**全部判死**

**为什么要建这个工具。** §22 的逐笔分解给出了一个残酷的事实：06 的**毛利只有成本的 4.5%**，
且 ~62% 的单子被止损直接扫掉 ⇒ **瓶颈在进场，不在出场**。既然出场怎么改都没用（§6 / §22 共 4 次同类失败），
那就**别再猜下一个信号，先造一个筛子**：在写任何策略代码之前，把一个候选进场信号
「**有没有方向信息 / 成本后能不能活 / 离打平差几倍**」一次算清。

**三层口径（冻结，见 `工具/_进场体检/README_口径.md`）**

| 层 | 做什么 | 回答什么 |
|---|---|---|
| **L0 纯进场** | 进场后**固定持有期**前瞻毛收益（点/手），**完全无止损** | 信号**有没有方向信息**（不受出场逻辑污染）|
| **L1 进场+固定止损** | 进场 + **2×ATR** 止损，到期未止损则期满平仓 | 这个小系统**成本后能不能活** |
| **量级判据** | `L1 毛均 ÷ 往返成本（点）` | 离打平**差几倍** |

冻结参数：`HOLD=12 根(5min≈1h)`、`止损 2×ATR`、`滑点 1 跳`、**固定 1 手（点数计，避开"波动率预算"这个混杂变量）**、
`MA13/SLOPE5/ATR14`（与 06 同口径，使基准锚可比）。**全部外生定死，不扫**（扫描持有期 = 调参）。
通过门槛五条：`n≥30` · `毛/成本≥2.0` · `L1 净>0` · `|t|≥2`（**按笔算，不按 bar**）· **多数品种同时满足**。

**被测的 6 个候选（全部经典外生给定，参数不扫）**：
`retrace_ma13`（**基准锚 = 06 的进场条件本身**）、`cross_ma13`、`breakout_20`（唐奇安）、
`tsmom_20`、`rev_2bar`（逆势）、`vol_break`（波动扩张）。

**结果（12 品种 × 5min × 2021-2023，共 72 组）**

| 观察 | 数据 |
|---|---|
| 过硬门槛 | **0 / 72** |
| L1 成本后净利 | **全负**；最好一格 = `vol_break`·棕榈油 **−0.41 点/笔** |
| **毛 / 成本比** | **全部 <1**；最好 **0.83 / 0.77 / 0.72 / 0.64** |
| L0 纯进场 | **≈0**（多数 ±0.3 点内）|
| 被止损扫掉占比 | **44%~57%** |
| 品种规律 | 成本点数最高的最差（天然橡胶 10.6 / 生猪 14.35 / 鸡蛋 3.16）|

★ **"不是慢，是没有一致的方向信息"** —— 这是本节最有信息量的一条。
持有期诊断曲线（1/2/3/6/12/24/48 根）上：焦煤、生猪**单调上升**（−0.11→+1.35 / 0.25→+21.1），
而白糖、鸡蛋**单调下降**（→−1.65 / −2.12），其余上下乱跳 ⇒ **符号跨品种完全不一致**。
若只是"偏慢的信号"，应当 12 个品种**一致地**随持有期上升；不一致 = **噪声特征**。
（唯一例外：生猪 48 根毛 21.06 点 vs 成本 14.35 ⇒ 比 1.46，**仍 < 2**，且仅 1/12 品种。）

**它意味着什么**：与 §6（06 三方向全败）、§20（08 三品种全负）、07（布林带负）
**互相印证** ⇒ 现在不是"某个策略没做好"，而是 **「价格形态类进场信号」作为一个类，
在这套成本结构下没有毛利**。之后的研究重心应从**数据维度**入手（见 §七之二 结论⑤⑥）。

**两条纪律（写进工具文档，防止它被当成"挖矿机"）**
1. **只能判死，不能判生。** 窗口 2021-2023 已污染，任何 ✅ 都不构成 edge 证据，
   只说明"值得换干净样本再验"。
2. **禁止把"批次里表现最好的那个"当成发现。** 跑 N 个信号 = N 次比较 ⇒ 挑最好的宣称有效就是过拟合（规则 2 禁区）。
   （本例中最好的那格只有 0.83，**离门槛太远，连多重比较校正都不必讨论**。）

**硬校验与工程细节**
- **未来函数截断检验 14,400 项全部通过**（6 信号 × 12 品种 × 200 抽样）：
  对每根抽查点，用 `data[:i+1]` 重算 `sig[i]`，必须与全量结果**逐一相等**。
- ⚠️ `_atr` 原为 Python 循环（5.3 万根/品种）⇒ 上万次抽样下**根本跑不完**，已改**累计和向量化**，
  并验证与 06 原版**逐值一致**（最大偏差 1.1e-12）；关键是**复刻了预热期 `max(1, i-n)` 的部分窗口行为**，
  而不是照抄 `pandas.rolling(14).mean()`（后者在预热期给 NaN，与 06 不一致）。
- 数据缓存 `工具/_进场体检/数据/*.csv`（12 品种 × 53,003 根，一次拉取后所有信号复用同一份 ⇒ 保证可比）。

## 八、值得注意的工程细节

仓库里有大量「踩坑注释」，它们记录了**为什么不能用看起来更聪明的方式写代码**：

- **主连合约不能跨段拼接**：换月会跳空（实测价格从 9700 跳到 1350），
  拼接后 ATR/均线全废、信号数暴涨一个数量级
- **天勤主连代码已自带 `KQ.m@` 前缀**，再拼一次会变成 `KQ.m@KQ.m@DCE.jm`
- **纳秒时间戳必须直接 `unit="ns"`**，先除 1e9 会全部落到 1970-01-01
- **`get_kline_serial` 返回的是预填 NaN 的定长数组**，`len(s) > 0` 不能作为「有数据」判据
- **`quote.margin` 在回测中是静态快照**，老合约返回占位值，不可用于动态保证金
- **隐藏 ≠ 移动**：隐藏属性不改路径（程序零影响），移动改路径（按路径查找的代码会静默失效）
- **行尾（CRLF/LF）必须用 `.gitattributes` 固化**，否则 Windows 下 `.bat` 会被
  编辑器写成 LF，导致 cmd 把 `REM` 当命令执行
- **`git ls-files` 必须加 `-c core.quotepath=false`**：否则中文路径被转义成八进制，
  任何按路径 `os.path.isfile()` 的统计都会静默返回「文件不存在」。
  ★ 本项目已在多个脚本里踩过：曾据此得出「仓库只有 19 个文件、0.5 MB」的错误结论，
  实际是 547 个文件、65 MB（问题 14）
- **`gitignore` 没有「例外套例外」**：给已跟踪文件新加忽略规则**不生效**，
  必须配一次 `git rm --cached`；反过来，未跟踪文件想豁免也要求规则顺序正确
  （先 `回测结果/**/*.html`，再 `!回测结果/**/*_参数.json`）

这些注释数量较多，但它们是本仓库中**最有价值的部分**——它们记录的是无法从代码本身
读出的「为什么」。

### 开发过程中沉淀的操作纪律

1. **跨文件常量对比必须逐行打印人眼核对** —— 正则只用来筛候选，结论绝不直接来自正则。
2. **多行文本比较一律用 `difflib`**，禁止按下标 `zip` 比长度不同的序列。
3. **判断「某开关生效了吗」要看开关本身**，不能看它影响的函数。
4. **引擎类代码必须先写合成数据单元测试再碰真实数据** —— 真实数据跑一次就污染样本外。
5. **中文变量名紧贴 Python 关键字会出语法错误**（`in腿` / `not腿`），跑之前一律 `ast.parse` 静态检查。
6. **模拟盘在跑时，不要开第二个 `TqApi` 做数据探查**（会抢连接卡死）。
7. **检查型脚本必须先判「有没有数据」，再判「数据是否正常」。**
   空集合走 `else` 分支 = 假肯定，比抛异常危险得多。
   （实例：某诊断脚本一条数据都没取到，却打印「✅ 全部正常」——因为异常没被接住。）
8. **日期键型必须统一**，纳秒时间戳当字符串用会得到「每根 bar 都是新月份」这类假结果。
9. **`git ls-files` 一定要加 `-c core.quotepath=false`** —— 中文路径不加会被转义成八进制，
   导致按路径的统计静默返回「文件不存在」，我曾据此两次报出错误的仓库体积。
10. **数据通道按周期选**：日线级研究用**实时模式**拉历史（一次到位、字段真实）；
    回测模式留给分钟级长历史，且注意回测模式下**主连日线 `volume` 全为 0**
    （实时模式同一日期真实），另外**回测模式下 `get_quote` 会去查已摘牌的历史主连合约**
    而报 graphql 错误。
11. **一个预注册结论也要按硬校验判定**：止损组胜率、分组笔数和、初始资金与逐笔盈亏对账、
    止损成交价是否落在入场价不利侧 —— 这几条曾分别抓出记账错误、丢笔、说谎的标签。

## 七之七、2026-10-13：换月孤儿仓三连修 + 订单流探针初探

1. **MA13 模拟盘双开陷阱**：调查进程发现 venv 一套 + 系统 Python 一套并行跑（共 4 个 PID），只重启一套、另一套仍用旧脱管逻辑裸奔。教训：杀进程须按「全部 PID」而非「一套」。
2. **孤儿扫描时序盲区（v2 修复 `873b6ba`）**：v1 换月检测条件 `if not underlying` 在 boot 接管**先**把 underlying 落盘为当前主连后**永远不触发** ⇒ 历史孤儿仓（修复前开的旧合约）仍隐形。离线 mock 7 场景全过却漏了「boot 先于对账」的真实启动时序。
   - 教训：**mock 测试必须覆盖真实调用时序**；「测试全过」≠「真实路径已覆盖」。
   - v2 改为每次对账扫描 + exclude 跟踪合约 + 防重闸门（未归零不重复报单 / 部分成交补报 / WAIT 事件节流），18 场景全过。
3. **近似订单流探针（实验中，`工具/_订单流探针/`）**：用 SimNow 五档快照算五档量失衡 vs 未来 20 tick mid 收益的 Spearman，多品种 ρ 显著 ≠ 0（al2612=0.79 / zn2612=0.59 / al2701=0.55 等）。
   - ⚠️ **不构成 edge 证据**：SimNow 盘口无真实主力行为，且 tick 级 mid 强自相关 + bid-ask bounce 会造成伪相关。
   - 真验证需交易所 Level-2 / 逐笔行情授权（付费+授权）——这是形态维度穷尽后，唯一未触及的数据维度切口。
4. **首发分布解析 + 随机进场对照（`工具/_首发分布/`）**：把一篇方法论论文的「离散三跳边界 → 吸收马尔可夫链」（§5.2）落到本项目真实 5min 数据，用**完全独立的方法**复核「价格类信号无方向信息」这一结论。
   - **自检**：论文示例 `p_止盈 = 0.666180235` 被 **9 位精确复现**（第 3 步 `u³ = 0.074088` 亦逐位一致）；解析 DP 与 20 万次蒙特卡洛在 **3 倍标准误**内一致。
   - **⚠️ 发现论文自身一处口径问题**：正文「20 步 p_R = 0.136413029」与它自己表 2 的「累计止损」列（本工具 0.197387）不符，反而与表 2「未触及」列（0.136433）同量级 ⇒ 判为**论文正文列名标注问题**；本工具以表 2 的逐步递推为准。
   - **核心发现（12 品种 × 2021-2023，已污染窗口）**：
     ① **46% 的止损率是几何必然，不是策略缺陷** —— 随机时点进场的止损率 **0.4823**，信号进场 **0.4636**，几乎一致 ⇒「2ATR 止损 + 12 根持有」这个结构本身就会扫掉约一半单子。**这为 §结论⑤「62% 被止损扫掉」提供了归因：不是 06 的错**。
     ② **信号相对随机时点的毛增益 = +0.551 点/笔，跨品种 t = +1.76 < 2（不显著）**，且 **8 正 4 负、符号不一致 = 噪声特征** ⇒ 与 §七之六·23 的 72 组判死**互相印证**。
     ③ `u/(u+d) = 0.5005`（12 品种全在 0.487~0.508）⇒ 5min 涨跌**完全对称、无方向偏差**。
   - **方法论意义**：本项目第一次用**「随机进场对照」**这种零假设检验（而非"回测看盈亏"）判定信号价值：与随机时点比，而不是与 0 比。
   - **功效检验（论文 §11.3）**：由真实 `(Δ, σ, n)` 反算**最小可检测效应** = 0.55~6.27 点/笔，而「值得交易」门槛（2×成本）= 2.6~28.7 点 ⇒ **`mde ÷ 门槛` = 11%~43%，全部远小于 1** ⇒ 若信号真有能覆盖成本的 edge，此样本量**必然检出** ⇒ **排除「样本量不足」这个替代解释**。（`required_n(Δ=0.1, σ=2.6)=5305.8`、`n_eff/n(ρ=0.3)=0.5385` 均复现论文。）
