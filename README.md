# 天勤量化

一个人从零搭的期货量化系统。2026 年 9 月开始，Python + TqSdk。

目标不是找一个能赚钱的策略，是把「一个想法」到「真实下单」这条路走通，
并且能证明它没有偷看未来。

> 个人学习与研究项目，非投资建议。所有回测都是历史模拟，不代表未来收益。

## 我做了什么

**一条从想法跑到下单的链路。**
研究脚本 → 回测 → 模拟盘 → 云端实盘 → 台账对账，中间没有断点。
现在日内 5 个品种并行跑着，订单真的会发到云端（模拟撮合账户，不是真钱）。

**把「防未来函数」做成机器能查的四层检查。**
不靠自觉：静态扫描代码有没有引用未来数据；把数据尾部截断，看结果变不变；
把未来数据涂成乱数，看信号跟不跟着变；再给这几层检查本身写元测试。
任何一层不过，那段回测就不许进结论。

**风控按出过的事写，不按教科书写。**
账户回撤熔断做成闩死加落盘，重启不自动复位，必须人工解除；
主循环异常时整体重启会话而不是原地重连，避免某一路订阅静默失效；
单实例锁防止两份进程同时下单；重启后止损线丢了会按统一公式补挂；
每次启动归档一份代码快照，事后能查「当时跑的是哪一版」。
每一条都对应一次真实事故，不是设计时想到的。

**盘后对账，把账本和权益拆到能对上。**
这一步抓出了最贵的问题：台账自己算出来是赚的，账户权益却是亏的，两个数差了七万。
拆开是三个独立的记账错误——「成交价」字段存的是信号价、账户切换点没分段、
换月窗口把新旧合约配成了一对。现在对账只认账户权益，账本算出来的数只当参考。

**想出来的东西一个个试，走不通的照实写。**
价格类信号、出场改造、跨品种传导、非价格因子，跑过的都留了记录：
用什么判据、结果是多少、为什么换参数也救不回来。
不看结果好不好看再决定写不写，被自己的数据推翻的结论也留在正文里。

**做了套自己用的复盘工具。**
单文件 HTML，双击就开，不用装环境不用起服务器。
点一笔成交，图直接跳到那一笔，K 线、均线、分时一起看。

## 现在的结果

模拟账户跑了 37 个交易日，权益从 100 万变成 99.4 万。

**没有一个能稳定赚钱的策略。** 这句放在这儿，不用翻到文末才看到。

在跑的 06 MA13 已经验证过没有 edge，继续跑只有一个目的：
验证工程链路是不是真能跑通，不是验证策略。

## 仓库结构

```
lib/          回测与实盘引擎、账户熔断、台账、代码快照
策略/         各策略及其历史（06 模拟盘在跑，其余冻结或收档）
工具/         进场体检、排列扫描、非价格数据、数据底账、复盘终端
回测结果/     参数与说明
实测记录/     模拟盘对账
```

## 技术栈

Python 3.12 · TqSdk · SQLite · pandas · 单文件 HTML
