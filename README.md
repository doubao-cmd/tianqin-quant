## 一、这个系统在解决什么问题

做策略研究时，真正花时间的从来不是「想出一个指标」，而是**让策略从研究代码
安全地活到实盘，且能证明它没有偷看未来**。本仓库围绕这一条主线构建：

```
想法 → 回测（样本内） → 样本外验证 → 模拟盘 → 云端实盘 → 台账对账 → 异常熔断
         ↑                                              │
         └──────────── 样本外只跑一次，绝不回头调参 ────┘
```

### 核心设计原则（写死在项目里，不可绕过）

| 原则 | 落地方式 |
|---|---|
| **禁未来函数** | 信号只用已收盘 K 线，成交价取**下一根开盘价**；禁用 ZigZag 等重绘指标 |
| **先有逻辑再写代码** | 不为提高胜率叠加过滤条件、不扫描参数择优、不做单品种专属标定 |
| **样本内外分离** | IS / 验证 / 期末考三段隔离，样本外只跑一次，**看过即污染** |
| **单变量迭代** | 每次只改一处逻辑，改完立即回测记录，便于归因 |
| **风控独立于策略** | 账户级回撤熔断 + 会话异常重启，与信号逻辑解耦 |

这四条是**项目级铁律**，不是建议。代码里有多处在注释中标注了对应的踩坑记录。

### ★ 防未来函数：4 层机器证明（本仓库的差异化卖点）

> 人人都怕未来函数，但多数人只靠「自觉」。本项目把它变成**可机器验证**的 4 层防线——这也是面试官最容易一眼记住的点。

| 层 | 做法 | 证据 |
|---|---|---|
| ① 静态 AST 扫描 | 在语法树层面禁止「读未来索引」类写法 | 可挂 CI |
| ② 截断检验 | 对每根 `i` 用 `data[:i+1]` 重算 `sig[i]`，须与全量逐位相等 | **14,400 项全部通过** |
| ③ 涂改未来 | 把未来 K 线涂成 NaN 重算，结果必须不变 | 与 ② 互证 |
| ④ 元测试 | 故意构造已知含未来函数的案例，工具**必须报出** | 测试工具自身也被测 |

配套工具 `工具/_进场体检/未来函数对照.py` 更进一步：**故意逐级注入未来信息**（随机 → 知下一根 → 知期末方向 → 知整条路径），把「违规风险」变成「信息价值测量仪」——结论是曲线**阶跃**而非斜坡（见 §七之七·9），即渐进调参无积累回报，**须换信息源而非琢磨价格形态**。

### 引擎接口

`lib/engine.py` 提供 5 套策略的回测与实盘入口，签名对称（`run_backtest_X` / `run_live_X`）：

| 策略 | 回测入口 | 实盘入口 |

## 三、风控与稳定性防护

这部分是本仓库投入精力最多的地方——**因为它解决的是「策略会死」而不是「策略赚不赚」**。

| 防护 | 触发条件 | 动作 |
|---|---|---|
| 账户回撤熔断 | 权益回撤达阈值（默认 20%） | **闩死** + 跨会话持久化，重启不自动复位 |
| 会话异常重启 | 引擎主循环异常退出 | 整体重启会话（而非原地重连） |
| 核心单实例锁 | 检测到已有核心进程 | 拒绝启动，防止双份下单 |
| 止损线丢失补挂 | 启动/重连后持仓无止损 | 用统一公式重算止损线 |
| 滑点/成交偏离统计 | 每笔成交后 | 记录决策价 vs 云端成交均价差 |
| 运行前代码快照 | 每次启动 | 归档代码版本，可追溯 |

### 两个值得说明的设计决策

**1）熔断用「重启整个入口」而不是「原地重连」**

引擎每次启动会自建 7 个 serials（行情/账户/持仓各一路）。断线后原地重连，
只要漏掉一路重连，该路就静默失效——表现为「持仓裸奔且无人察觉」。
因此宁可整体重启，也不做原地重连。

**2）回撤熔断必须闩死 + 持久化**

如果熔断只在内存里，重启就自动复位 ⇒ 相当于没有熔断。
本项目把熔断状态落盘，重启后仍保持闩死，需人工确认才解除。

## 四、研究方法论

### 样本区间（三段隔离）

| 区间 | 时段 | 用途 |
|---|---|---|
| 样本内 IS | 2016-01-01 ~ 2019-12-31 | 逻辑开发与检验 |
| 验证 | 2020-01-01 ~ 2024-12-31 | 跨年矩阵、稳健性检验 |
| 期末考 | 2025-01-01 ~ 2026-09-30 | 最终验证，**只跑一次** |

> 上市较晚的品种（纯碱 / 苯乙烯 / 生猪）练习区间单独后移，横向对比时需注意。

### 前向诊断工具

`工具/MA13前向诊断.py` 是**只读诊断**工具：不改策略、不下单、不调参，
只回答一个问题——**信号发出后若不止损，价格是先走对还是先走错**。

- 「先走对」比例 ≈ 50% ⇒ 信号本身无 edge，换出场规则无用
- 显著 > 50% ⇒ 信号有 edge，利润是被出场规则切掉的

这个工具存在的意义是：**用数据替代猜测**，避免在无 edge 的逻辑上反复调参。

### 本地自检

防护层代码均配有离线自检脚本，不依赖网络即可验证：
- `工具/自检_回撤熔断_20261008.py`（32 项）
- `工具/自检_会话重启_20261008.py`（13 项）
- `工具/环境自检.py`、`工具/模拟盘自检.py`（48 个入口）

## 五、技术栈与运行

### 依赖

Python ≥ 3.9（实测基准 3.12.1 / Windows 10）。第三方依赖**只有 3 个**，全部由 [tqsdk](https://github.com/shinnytech/tqsdk-python) 生态提供：

```
tqsdk >= 3.10.2      # 行情 / 历史数据 / 回测 / 模拟交易 / 实盘交易
pandas >= 1.1.0      # 回测指标、台账聚合、回撤统计
numpy  >= 1.20.0     # 指标向量化
```

```bash
# 方式一（推荐，日常开发）
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt

# 方式二（需要完全复现实测环境时）
pip install -r requirements.lock.txt
```

> `requirements.txt` 只声明**直接依赖**（实测扫描全仓库 13 个 `.py` 文件得出），
> tqsdk 的 14 个传递依赖交给 pip 自动解析，手工钉版本反而容易和它的约束打架。
> `requirements.lock.txt` 是本机 32 个包的**精确快照**，用于换机复现。

其他说明：
- **不需要 TA-Lib**：技术指标全部自行实现（只用 pandas/numpy），避免指标库版本差异造成口径漂移。
- **不需要 vnpy**：本项目直接用 tqsdk，不走 vnpy 生态。
- **Windows 若卡在编译依赖**：改用 tqsdk 官方 exe 安装包，见[官方安装说明](https://doc.shinnytech.com/tqsdk/latest/installation.html)。

2. 双击 `天勤量化.bat` 进入工作台，或直接运行对应脚本。

### 1. 出场与开仓在同一根 K 内相邻执行（无冷却期）

`ma13_live_multi.py` 的出场判定与开仓判定在**同一次回调内前后相邻** ⇒ 时间止损到期的同时若回踩信号成立，会「刚平仓、原方向、原价位立刻重开」（实测 JD2611：`10:50:00 多平 8 手 @3740` 与 `10:50:00 多开 8 手 @3740` 同一分钟）。

**未修复，且是刻意的**——加冷却期属于「叠加过滤」（违反规则 2），也没有证据表明它能改善结果。
**记下来是为了让「为什么不修」本身可被审查**（`grep cooldown/冷却/last_exit` 零命中，确认不是漏看）。

### 6. ★★ 三个出场改造全部失败，暴露了策略的真实收益结构

2026-10-09 在 `2025-03~2026-03` 跑了三个出场方向，**全部崩塌**：

| 方向 | 改动 | 等权夏普 |
|---|---|---:|
| 原版（对照） | — | 1.593 |
| 方向1 | 加 2×ATR 止盈 | −4.036 |
| 方向2 | 回踩 MA13 平仓 | −2.447 |
| 方向3 | 5min → 1min | −0.878 |

**方向2 的失败模式最干净**：75% 的单子由「回踩均线」平仓——因为**进场条件本身就是「回踩 MA13」**，开仓后约 **1.5 根 bar 就退出** ⇒ **出场逻辑与进场逻辑自相矛盾**（时间止损占比从 37% 崩到 4%）。
**方向1（止盈）**则把时间止损从 341 笔压到 11 笔，全改由止损出场 ⇒ 趋势没走完就被截断，四腿爆仓。

⇒ **根因（三方向共同指向）**：MA13 的收益结构是「**小止损 + 让利润跑**」，**任何把出场提前、砍短的改动都会崩**。这也是**后续不再往出场加条件**的依据（规则 2）。

### 8. ★★ 回测与模拟盘的仓位口径曾不一致（已修）

回测（10-07 起）用**复利**（当前权益 × 1%），模拟盘 `RISK_EQUITY=200000.0` **强制锁死 20 万** ⇒ 模拟盘注释「与回测 INIT 严格对齐」**是错的**。

**处置（用户拍板方案 A：改回测、不动模拟盘）**——理由：锁死 20 万保住单腿收益可加性（`E[组合]=ΣwᵢE[腿ᵢ]`），且改模拟盘要重启在跑进程。实现为两个开关：`GAP_FILL=True`（止损按跳空保守侧成交）、`COMPOUND=False`（手数基数固定 20 万）。
**归因结论（2021-2023）**：`COMPOUND` 影响巨大（927%→420%）但**回撤更小、夏普更高**（复利是放大仓位赌出来的）；`GAP_FILL` **对总收益零影响**（止损亏更多 ⇄ 提前离场少赚，恰好对冲），保留它 = 口径更诚实。

### 9. ★ 两次「工具报了 bug，其实是工具自己错」

体检脚本（9 项检查）第一版报 **3 个 P0，复核后全是假报**：① 行数不同却**按下标 zip 比对**（每行都被算成不同）⇒ 应用 `difflib.unified_diff`；② 元组一次赋值 `MA_N, SLOPE_N, ATR_N = 13, 5, 14` 被正则取错位；③ 只看 `_base_hand` 有没有 `equity`，**没看 `COMPOUND` 开关本身**。
修正后 **P0 = 0 条**，13 项常量逐字一致。

⇒ **两条纪律**：① **跨文件常量对比一律逐行打印人眼核对**，正则只用来筛候选，**结论绝不直接来自正则**；② 判断「某开关生效了吗」**要看开关本身**，不能看它影响的函数。

### 10. ★ 止损成交价的理想价假设：查了，结论是「改不改都不影响数字」

模拟盘实测成交价与止损线的偏差达 **+0.04 ~ −22.11 点**，而回测 `exit_price = stop_price`（零滑点/零跳空）⇒ 理论虚高。实测（4 格全组合）：`GAP_FILL` **对总收益/夏普/笔数逐位无影响**。
⚠️ 但保留保守侧仍有意义：那 −22.11 点是**实测真实存在**的滑价，不用保守假设就永远体现不出来；**对冲掉只是本窗口的巧合**。成本为零、口径更诚实，故保留。

## 七之二、同一天做的三张预注册卡：三连无效（2026-10-10）

### 15. 截面持仓量因子「增仓滞涨」：两轮实验都被证伪（卡已收档）

| 实验 | IS 结果 |
|---|---|
| 首版（无止损） | **−141.1%**（53 笔，胜率 47.2%）|

### 16. TSMOM（12 月时序动量）：无效，且撞上 momentum crash（卡已收档）

IS 权益 200,000 → 50,936（**−74.5%**），夏普 −0.298，回撤 −80%。2017-2018 正是 2016 供给侧大涨后的回落震荡期 = 文献里 momentum crash 的形态。

### 17. 出水芙蓉：日频 0 信号，换 15min 后证伪为无正期望（两层独立失败）

**第一层（日频）**：冻结参数（≥3×均量20）下 5 年 × 9 品种 = **0 个信号**。实测日频放量尖峰集中在 **1.5~2.5 倍**区间 ⇒ 「放量数倍」在日频商品上**经验性近空集**。

**第二层（15min 真回测）**：信号充足（**214 笔**，6 项硬校验全过），但 **等权夏普 −0.013、正夏普 2/9**，判定门槛（>1.0）差得远 ⇒ **无效收档**（OOS 未跑）。
⇒ **两层独立失败**：日频是「连开仓都没有、无法评估」，15min 是「信号充足但无正期望」。**只有换到短周期才算真正把这个策略证伪了一次** ⇒ 方法论实证「**日频 0 信号 ≠ 策略无优势，必须短周期才能真正证伪**」。

### ★★ 多张预注册卡连续无效之后，最有价值的是这五个方法论结论

**① 预注册卡冻结前必须先做「信号频率预算」。** 频率可用历史数据**解析计算**（半小时），不需要先建引擎。本次是建完全套引擎 + 29 项单元测试后，才发现冻结参数下一个信号都没有。
⇒ **今后固定立卡流程：定义 → 频率预算 → 冻结 → 引擎 → 单元测试 → 跑。**

**② 「零干净样本外」在天勤免费版下是数学问题，不是纪律问题。** 9 品种主连日线 `data_length=3000`（本应回溯 ~12 年），但**最早一律 2016-01-04**（2613 根 = 至今天的全部交易日）⇒ **能取到的区间恰好等于被跑过的区间**，「找一段没人看过的年份」在当前数据源下**不存在**。同理 carry 在免费数据下做不严谨（实测 4/4 具体合约历史日线全空）。要突破须换数据源（如 akshare 单合约日线，可回溯到 1990s）。

**③ 比率/阈值型信号，立卡前必须做「量纲稳健性检查」——不只查「有没有信号」，还要查「会不会永远有信号」。** 仓单 `rc = 仓单_t / 仓单_(t-20) − 1` 对**基数**敏感；4/5 品种基数小且频繁归零 ⇒ `rc` 爆量（甲醇 rc_std **37401%**）⇒ ±10% 闸门 64%~88% 天数常开、**退化成「几乎永远在场」**。（与 §15 的 `OI_THRESH` 日频退化是**同一种病**。）

**④ 推荐任何新因子/策略前，先查项目「已试清单」。** 现有已试：01-04 + 05/06/07/08 + 仓单 / 截面持仓量 / 截面基差 / TSMOM / 出水芙蓉 / carry / 保本止损 / 六类价格进场信号 / 威科夫 5 形态 / SMC 2 组件 / 布林带+RSI 战法 —— **全部为负或无正期望**。

**⑤ ★★★ 判断一个策略是否「已经死了」，先看「毛利 ÷ 成本」的**量级**，再看方向。**

## 七之三、★★★ 问题 19：一个让全部收益数字翻倍的记账 bug（2026-10-11）

**本项目至今最重要的自审记录。它不是策略问题，是「我在自己的回测代码里造出了一个系统性虚高，然后拿它当证据用了两个多月」。**

**起因**：原计划做「参数孤峰/高原检测工具」，第一步只读诊断时顺手做了一次「报告收益 vs 逐笔收益」对账，发现：

> **36 份产物：报告收益为正 34 份，逐笔收益为负 35 份。**

矛盾太大，不可能用「策略不好」解释 ⇒ 停下来查根因。

**根因：两条记账路径不一致。** 路径①逐笔 `pnl = pos*(exit−entry)*MULT − exit_cost`（**正确**）；路径②权益曲线 `if pos != 0: equity += pos*(close[i]−close[i−1])*MULT`（**错误**）——第 274 行的 `if` **不排除开仓 bar 与平仓 bar**：
边界误差 = `Σ s·hand·MULT·[(close[开仓bar] − open[开仓bar]) + (出场价 − close[平仓bar])]`
这个误差**每笔交易都有**，且在有趋势的市场里与持仓方向正相关 ⇒ **系统性偏向盈利侧**。

**量化**（甲醇 2021 全年，913 笔）：

| 记账方式 | 期末权益 | 收益 |
|---|---:|---:|
| 路径① 逐 bar close（当时策略在用）| 546,260 | **+173.13%** |
| 路径② 逐笔 open→open（**正确口径**）| 64,270 | **−67.86%** |
| **边界误差** | **481,990（占路径①收益的 139.2%）** | |

全部 36 份：报告收益合计 **+6,516%**，逐笔收益合计 **−2,973%**。

**修复**：
(a) `equity` 只在平仓时结算 `pnl`（含双边成本），持仓期另存 `eq_mark`（仅画图/回撤/夏普）；
(b) 逐笔 `pnl` 改为含双边成本 ⇒ **`Σpnl ≡ Δequity` 成为恒等式**；
(c) ★ **加自动对账断言**：`if abs(equity − INIT − Σpnl) > max(1.0, n*0.01): raise AssertionError(...)` —— **没有这条断言，同类 bug 一定会再犯**。

**修复后重跑：真相**

| 窗口 | 正夏普品种 | 等权夏普 |
|---|---|---:|
| 开发窗 2021-2023 | **0/12** | −1.51 |
| 前向窗 2024-2025 | 2/12 | −1.39 |
| 探针窗 2026 | **0/12** | −3.25 |

⇒ **MA13 超短线没有 edge，之前所有 +100%~+900% 的数字 100% 由这个 bug 产生。**

**我在这次调查中的 4 个假设，前 3 个是错的**：① 逐笔 pnl 漏记开仓成本（❌ 差额 1231 万 ≠ 302 万）；② bar 的 open==close 是伪 bar（❌ 实测 5min 45.4%、日线 15.2%，是真实 OHLC）；③ 手数与盈亏相关致选择性偏差（❌ 相关系数 ≈0.017）；④ **两条记账路径口径不同（边界错配）✅ 成立**。
⇒ **没有独立复现之前，任何「看起来很合理」的推断都可能是错的**（与 §9、§18 是同一教训的第三次出现）。

**为什么会犯（以及为什么值得写进仓库）**：① 两套记账并存、且从未被强制对齐；② **没有断言、没有对账**；③ **数字太好看时本该先怀疑**——「20 万本金、8 手封顶、回撤 7%、收益 +900%」这组数早该被质疑（我曾写下来「这个组合可疑」，**但写下来 ≠ 查清楚**）；④ 它证明了自审机制的价值：**副产品式的检查，常常比正面检查更早发现问题**。

   - ★ **这份分解的意义**：它把「**别再无止境地换信号了**」从一句判断，变成了一个**可量化的结论** —— **信号维度只解释 5% 的变异**。这是整套「价格类信号批量证伪」的**收口证据**。

9. **★★ 未来函数对照：把「未来函数」从违规风险变成测量工具（2026-10-14）**（`工具/_进场体检/未来函数对照.py`）
   - **背景**：用户提出「过拟合其实可以有；我们现在所有价格策略都是**欠拟合**（连历史行情都抓不住）」⇒ 本实验就是给这个问题一个可证伪的答案。
   - **设计（★ 故意违规，非策略）**：**固定进场点（`retrace_ma13`）、成本、`HOLD=12`、2ATR 止损——唯一变量是「方向里注入了多少未来信息」**：
     `B0` 随机方向（零信息基线，20 次均值）/ `B1` 真实信号（现状）/ `F1` 知下一根 / `F2` 知持有期末方向 / `F3` 知路径（只在「不会先碰止损」时进）。

     | 档 | 注入的信息 | 毛/成本 | 止损率 | 单笔净均 |
     |---|---|---:|---:|---:|
     | **B0** | 随机方向（零信息）| +0.084 | 46.5% | −3.76 |
     | **B1** | 真实信号（现状）| +0.110 | 46.4% | −3.46 |
     | **F1** | 知下一根 | **+0.401** | 45.5% | −3.31 |
     | **F2** | 知期末方向 | **+7.341** | 16.4% | +21.91 |
     | **F3** | 知路径 | **+10.103** | **0.0%** | +31.26 |

   - **四条结论**：
     ① **`B1 − B0 = +0.026`** ⇒ 真实信号价值 ≈0（独立确认 ·4 的 `+0.551 点 / t=1.76`）。
     ② ★ **「只知下一根」也只有 0.401**（门槛的 1/5）⇒ 解释了为何**叠加过滤 / 形态 /「半步条件」全部无效**。
     ③ ★★ **曲线是阶跃的，不是斜坡**：`B0→B1→F1` 几乎平（+0.084→+0.401），而 `F1→F2` **跃升 17 倍**（→+7.341）⇒ **信息在此结构下是「阈值型」，没有「半懂」的中间地带** ⇒ **渐进改进（加特征/调参）在曲线上没有可积累的回报**。
     ④ **`F3` 止损率 → 0%** ⇒ 那 46% 的几何止损率，是「**不知道路径**」的代价。
   - ★★ **对「欠拟合说」的裁决**：**诊断对**（IS 就负 = 欠拟合，扣「过拟合」帽子是用错词）；**归因错**（不是容量不足 —— 加容量曲线几乎平，只有注入**未来信息**才跃升）；**处方反**（加参数无用，须**换信息源**）。
   - **副产品**：`B0 ≈ +0.084`（≈0）⇒ **亏损不来自「做反了」，来自成本** ⇒ 印证「信号层 ≈0，成本把它变负」。
   - **内置对拍 ✅**：`B1` ≡ `进场体检.py --signal retrace_ma13`（逐品种一致）。
   - ⚠️ **局限**：窗口 2021-2023 已污染、5min、单一进场点集合、F3 为筛选后样本（保留 ~84%）。`F1/F2/F3` **全部违反规则 1**，只是对照，**不得当策略用**。

## 八、值得注意的工程细节

仓库里有大量「踩坑注释」，记录**为什么不能用看起来更聪明的方式写代码**：

- **主连合约不能跨段拼接**：换月会跳空（实测价格从 9700 跳到 1350），拼接后 ATR/均线全废、信号数暴涨一个数量级
- **天勤主连代码已自带 `KQ.m@` 前缀**，再拼一次会变成 `KQ.m@KQ.m@DCE.jm`
- **纳秒时间戳必须直接 `unit="ns"`**，先除 1e9 会全部落到 1970-01-01
- **`get_kline_serial` 返回预填 NaN 的定长数组**，`len(s) > 0` 不能作为「有数据」判据
- **`quote.margin` 在回测中是静态快照**，老合约返回占位值，不可用于动态保证金
- **隐藏 ≠ 移动**：隐藏属性不改路径（程序零影响），移动改路径（按路径查找的代码会静默失效）
- **行尾（CRLF/LF）必须用 `.gitattributes` 固化**，否则 Windows 下 `.bat` 被写成 LF 会让 cmd 把 `REM` 当命令执行
- **`git ls-files` 必须加 `-c core.quotepath=false`**：否则中文路径被转义成八进制，任何按路径 `os.path.isfile()` 的统计都会静默返回「文件不存在」（曾据此得出「仓库只有 19 个文件、0.5 MB」的错误结论，实际是 547 个文件、65 MB —— 见 §14）
- **`gitignore` 没有「例外套例外」**：给已跟踪文件新加忽略规则**不生效**，必须配一次 `git rm --cached`

这些注释数量较多，但它们是仓库中**最有价值的部分**——记录的是无法从代码本身读出的「为什么」。

### 开发过程中沉淀的操作纪律

1. **跨文件常量对比必须逐行打印人眼核对** —— 正则只用来筛候选，结论绝不直接来自正则。
2. **多行文本比较一律用 `difflib`**，禁止按下标 `zip` 比长度不同的序列。
3. **判断「某开关生效了吗」要看开关本身**，不能看它影响的函数。
4. **引擎类代码必须先写合成数据单元测试再碰真实数据** —— 真实数据跑一次就污染样本外。
5. **中文变量名紧贴 Python 关键字会出语法错误**（`in腿` / `not腿`），跑之前一律 `ast.parse` 静态检查。
6. **模拟盘在跑时，不要开第二个 `TqApi` 做数据探查**（会抢连接卡死）。
7. **检查型脚本必须先判「有没有数据」，再判「数据是否正常」。** 空集合走 `else` 分支 = 假肯定，比抛异常危险得多。
8. **日期键型必须统一**，纳秒时间戳当字符串用会得到「每根 bar 都是新月份」这类假结果。
9. **`git ls-files` 一定要加 `-c core.quotepath=false`** —— 中文路径不加会被转义成八进制，导致按路径的统计静默返回「文件不存在」。
10. **数据通道按周期选**：日线级研究用**实时模式**拉历史（一次到位、字段真实）；回测模式留给分钟级长历史，但注意**回测模式下主连日线 `volume` 全为 0**（见 §18）。
11. **任何结论都要过硬校验**：止损组胜率、分组笔数和、初始资金与逐笔盈亏对账、止损成交价是否落在入场价不利侧 —— 这几条曾分别抓出记账错误、丢笔、说谎的标签。
12. **零成本先查、再动手**：跑 N 个候选 = N 次比较 ⇒ 只能用「能判死」的筛子先过一遍，禁止挑最好的当发现。
