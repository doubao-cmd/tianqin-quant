# 天勤量化 · 期货策略研究与实盘系统

基于 **TqSdk 3.10.2** 的期货量化研究与模拟/实盘交易系统。覆盖策略研究、回测、模拟盘、
实盘、风控防护、台账对账全链路，日内同时跑 5 个品种 × 8 条腿。

> ⚠️ **本仓库为个人学习/研究项目，非投资建议。所有回测结果均为历史模拟，不代表未来收益。**

---

## 一、这个系统在解决什么问题

做策略研究时，真正花时间的从来不是「想出一个指标」，而是**让策略从研究代码
安全地活到实盘，且能证明它没有偷看未来**。本仓库围绕这一条主线构建：

```
想法 → 回测（样本内） → 样本外验证 → 模拟盘 → 云端实盘 → 台账对账 → 异常熔断
         ↑                                              │
         └──────────── 样本外只跑一次，绝不回头调参 ────┘
```

### 核心设计原则（写死在项目里，不可绕过）

| 原则 | 落地方式 |
|---|---|
| **禁未来函数** | 信号只用已收盘 K 线，成交价取**下一根开盘价**；禁用 ZigZag 等重绘指标 |
| **先有逻辑再写代码** | 不为提高胜率叠加过滤条件、不扫描参数择优、不做单品种专属标定 |
| **样本内外分离** | IS / 验证 / 期末考三段隔离，样本外只跑一次，**看过即污染** |
| **单变量迭代** | 每次只改一处逻辑，改完立即回测记录，便于归因 |
| **风控独立于策略** | 账户级回撤熔断 + 会话异常重启，与信号逻辑解耦 |

这四条是**项目级铁律**，不是建议。代码里有多处在注释中标注了对应的踩坑记录。

### 引擎接口

`lib/engine.py` 提供 5 套策略的回测与实盘入口，签名对称（`run_backtest_X` / `run_live_X`）：

| 策略 | 回测入口 | 实盘入口 |
|---|---|---|
| 均线排列 | `run_backtest_align` | `run_live_align` |
| 布林带 | `run_backtest_boll` | `run_live_boll` |
| 摆动线 | `run_backtest_swing` | `run_live_swing` |
| 通用均线 | `run_backtest` | `run_live` |
| Pro 增强 | `run_backtest_pro` | `run_live_pro` |

统一仓位口径：**每腿风险 1% 权益、最小 1 手、每手保证金 ≤ 当前权益 30%**。
每手保证金按 `信号根收盘价 × 乘数 × 保证金率` 动态计算，并随权益缩水自动收紧。

## 三、风控与稳定性防护

这部分是本仓库投入精力最多的地方——**因为它解决的是「策略会死」而不是「策略赚不赚」**。

| 防护 | 触发条件 | 动作 |
|---|---|---|
| 账户回撤熔断 | 权益回撤达阈值（默认 20%） | **闩死** + 跨会话持久化，重启不自动复位 |
| 会话异常重启 | 引擎主循环异常退出 | 整体重启会话（而非原地重连） |
| 核心单实例锁 | 检测到已有核心进程 | 拒绝启动，防止双份下单 |
| 止损线丢失补挂 | 启动/重连后持仓无止损 | 用统一公式重算止损线 |
| 滑点/成交偏离统计 | 每笔成交后 | 记录决策价 vs 云端成交均价差 |
| 运行前代码快照 | 每次启动 | 归档代码版本，可追溯 |

### 两个值得说明的设计决策

**1）熔断用「重启整个入口」而不是「原地重连」**

引擎每次启动会自建 7 个 serials（行情/账户/持仓各一路）。断线后原地重连，
只要漏掉一路重连，该路就静默失效——表现为「持仓裸奔且无人察觉」。
因此宁可整体重启，也不做原地重连。

**2）回撤熔断必须闩死 + 持久化**

如果熔断只在内存里，重启就自动复位 ⇒ 相当于没有熔断。
本项目把熔断状态落盘，重启后仍保持闩死，需人工确认才解除。

## 四、研究方法论

### 样本区间（三段隔离）

| 区间 | 时段 | 用途 |
|---|---|---|
| 样本内 IS | 2016-01-01 ~ 2019-12-31 | 逻辑开发与检验 |
| 验证 | 2020-01-01 ~ 2024-12-31 | 跨年矩阵、稳健性检验 |
| 期末考 | 2025-01-01 ~ 2026-09-30 | 最终验证，**只跑一次** |

> 上市较晚的品种（纯碱 / 苯乙烯 / 生猪）练习区间单独后移，横向对比时需注意。

### 前向诊断工具

`工具/MA13前向诊断.py` 是**只读诊断**工具：不改策略、不下单、不调参，
只回答一个问题——**信号发出后若不止损，价格是先走对还是先走错**。

- 「先走对」比例 ≈ 50% ⇒ 信号本身无 edge，换出场规则无用
- 显著 > 50% ⇒ 信号有 edge，利润是被出场规则切掉的

这个工具存在的意义是：**用数据替代猜测**，避免在无 edge 的逻辑上反复调参。

### 本地自检

防护层代码均配有离线自检脚本，不依赖网络即可验证：
- `工具/自检_回撤熔断_20261008.py`（32 项）
- `工具/自检_会话重启_20261008.py`（13 项）
- `工具/环境自检.py`、`工具/模拟盘自检.py`（48 个入口）

## 五、技术栈与运行

### 依赖

Python ≥ 3.9（实测基准 3.12.1 / Windows 10）。第三方依赖**只有 3 个**，全部由 [tqsdk](https://github.com/shinnytech/tqsdk-python) 生态提供：

```
tqsdk >= 3.10.2      # 行情 / 历史数据 / 回测 / 模拟交易 / 实盘交易
pandas >= 1.1.0      # 回测指标、台账聚合、回撤统计
numpy  >= 1.20.0     # 指标向量化
```

```bash
# 方式一（推荐，日常开发）
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt

# 方式二（需要完全复现实测环境时）
pip install -r requirements.lock.txt
```

> `requirements.txt` 只声明**直接依赖**（实测扫描全仓库 13 个 `.py` 文件得出），
> tqsdk 的 14 个传递依赖交给 pip 自动解析，手工钉版本反而容易和它的约束打架。
> `requirements.lock.txt` 是本机 32 个包的**精确快照**，用于换机复现。

其他说明：
- **不需要 TA-Lib**：技术指标全部自行实现（只用 pandas/numpy），避免指标库版本差异造成口径漂移。
- **不需要 vnpy**：本项目直接用 tqsdk，不走 vnpy 生态。
- **Windows 若卡在编译依赖**：改用 tqsdk 官方 exe 安装包，见[官方安装说明](https://doc.shinnytech.com/tqsdk/latest/installation.html)。

## 七、已知问题与自审记录

这一节记录**我自己审自己代码时发现的问题**。它们的共同点是：
**在给出结论前必须先读源码取证，不能只看数据表象。**

### 1. 出场与开仓在同一根 K 内相邻执行（无冷却期）

`ma13_live_multi.py` 中，出场判定（第 722 行）与开仓判定（第 751 行）在**同一次
K 线回调里前后相邻**：

```python
if pos > 0 and (l <= s["stop"] or s["bars_in"] >= MAX_HOLD):
    s["pos"] = 0                      # ← 出场，把仓位清零
    ...
# 紧接着往下走
if pos == 0 and dir_trend != 0 and touch:
    ...                               # ← 此时 pos 已是 0，允许立即重开
```

**后果**：当一根 K 线同时满足「时间止损到期」与「回踩信号成立」时，
会出现「刚平仓、原方向、原价位立刻重开」。

**实测实例**（2026-10-09 鸡蛋 JD2611）：
```
10:50:00  多平 8 手 @3740   时间止损=True   持仓期浮盈 +1520
10:50:00  多开 8 手 @3740   ← 同价位同方向立即重进
```

**当前状态**：**未修复，且是刻意的**。
- 修复它属于「新增一个过滤条件」，违反项目规则 2（不叠加过滤）；
- 同时也没有证据说明加冷却期能改善结果（样本不足）。

**为什么仍然写在这里**：这是一个**已确认存在、但主动不修**的行为。
把它记下来，比藏起来更有价值——它让「为什么不修」这个决策本身可被审查。

> `grep -n "cooldown|冷却|last_exit"` 在 `ma13_live_multi.py` 与 `lib/engine.py`
> 中均零命中，可确认不是「漏看」而是「确实没有」。

### 2. 两类出场的性质截然不同（16 笔样本，2026-10-09 12:04 统计）

按出场原因把 16 笔拆开，盈亏分布是**反向**的：

| 出场方式 | 笔数 | 合计盈亏 | 平均每笔 | 判读 |
|---|---:|---:|---:|---|
| **时间止损** | 3 | **+9,440 元** | **+3,147** | 持仓期间有实质浮盈，被时限砍掉 |
| 价格止损 | 13 | **−17,620 元** | −1,355 | 开仓几乎立刻反向，**开仓即错** |

极端案例：棕榈油 10-09 多开 9638 → 时间止损平 9743，**单笔 +8,400 元**，
占全部正收益的 89%；而价格止损 13 笔每笔都在 −1,000 ~ −4,000 之间。

⇒ 结论：两类出场是**两个不同的问题**——
- 价格止损（13 笔，−17,620）指向「**入场逻辑在震荡市无 edge**」＝主要矛盾；
- 时间止损（3 笔，+9,440）指向「`MAX_HOLD=15` 可能偏短」＝次要矛盾。

⚠️ **但这里有一个统计陷阱，必须说破**：时间止损的 3 笔是**盈利被截断**，
价格止损的 13 笔是**亏损被截断**。两组不是同类样本，
直接比均值会高估「时间止损」的价值——真实情况是：
**如果放开 MAX_HOLD，13 笔价格止损里有多少会变成盈利，目前无法回答**，
因为它们在触及止损前从未被允许继续持有。

**按规则 4（每次只改一处逻辑），本项目不同时动这两处** ⇒ 先继续累积样本。

### 3. 平仓侧滑点系统性缺失

台账中 `FILLX`（滑点记录）多次显示「云端均价未就绪（未读到）」，
集中在**平仓**记录上（开仓侧正常）。推测原因是平仓后读取成交均价的时序过早。
样本累计 6 条，不足以定论，暂记为待观察项。

### 4. ⚠️ 回测结果文件里混了三种仓位口径（**最隐蔽的一个**）

`回测结果/06_MA13超短线/` 下 24 份 `_参数.json` **不是同一种口径跑出来的**。
判据是每份 JSON 自带的 `cost_assumption` 字段：

| 口径 | 份数 | 判据 |与实盘对齐 |
|---|---:|---|---|
| `固定20万` |16 | 含「目标风险2000」 | ✅ **是** |
| `复利` | 7 | 含「当前权益」，手数随权益浮动 | ❌ 否 |
| `阶梯` | 1 | 含「利润满40万」（已废弃的特殊加仓规则） | ❌ 否 |

**为什么「固定20万」才是对齐的**：模拟盘 `ma13_live_multi.py:114` 写死
`RISK_EQUITY = 200000.0`，即手数按固定 20 万基数计算，**与账户实际余额（约 100 万）
刻意脱钩**（注释里写明：否则名义敞口会放大 5 倍，且与回测无法对账）。

⇒ **只有 ✅ 那16 份能与模拟盘对账。**

**这个坑已经造成过两次误判**（都是我自己犯的）：
1. 曾把「PVC 3132 笔 / Sharpe 3.65」与「模拟盘 16 笔 / 19% 胜率」对比，
   **结论「回测 47% vs 实测 19%，策略有问题」是错的**——
   3132 笔那个数是 2021-2023 复利口径，拿它和三年前的实盘之外的历史比，
   而且口径本身就不同。
2. 曾把24 份结果横向排在一起，据此得出「2026 有两个品种崩了（螺纹钢 Sharpe −7.12、
   纯碱 −5.01）」——这个数字本身没错，但它属于哪个窗口、哪个品种曾被我张冠李戴过一次。

**处理方式**：
- 打标签脚本 `工具/标注_回测口径_20261009.py`（只读，自动生成）
- 索引表 `工具/_输出/_回测口径索引.md`（含逐份判定依据）
- **❌ 行的数字不是错的**，只是另一个口径下的历史存档，保留是为了可追溯；
  要变成 ✅ 需用当前脚本重跑（会覆盖原文件，建议先备份）。

**使用纪律**：横向比较只能只用 ✅ 行。

### 5. 诊断确认：成交价口径**不是**差异来源

曾怀疑「回测用下一根开盘成交、模拟盘记当根收盘价」是回测与实测背离的原因。
用 `工具/诊断_回测实测差异_20261009.py` 实测（同数据、只切换该一个变量）：

| 口径 | 笔数 | 胜率 | Sharpe |
|---|---:|---:|---:|
| 开盘成交 | 1797 | 29.0% | 1.96 |
| 收盘成交 | 1797 | 29.0% | 1.96 |

⇒ **零影响**。原因：止损判定用的是 `low[i]`/`high[i]`，成交价换成`close[i]`
只影响记账价，不影响信号是否触发。**该假设被数据否掉，无需修改。**

同一实验里另一项有影响：**允许/禁止出场后同根重开**
（笔数 1797 → 1611，Sharpe 1.96 → 3.12）。
⚠️ 但模拟盘**也是允许同根重开的**，单改回测会让两侧口径分叉 ⇒ **只记录，不动手**。

## 八、值得注意的工程细节

仓库里有大量「踩坑注释」，它们记录了**为什么不能用看起来更聪明的方式写代码**：

- **主连合约不能跨段拼接**：换月会跳空（实测价格从 9700 跳到 1350），
  拼接后 ATR/均线全废、信号数暴涨一个数量级
- **天勤主连代码已自带 `KQ.m@` 前缀**，再拼一次会变成 `KQ.m@KQ.m@DCE.jm`
- **纳秒时间戳必须直接 `unit="ns"`**，先除 1e9 会全部落到 1970-01-01
- **`get_kline_serial` 返回的是预填 NaN 的定长数组**，`len(s) > 0` 不能作为「有数据」判据
- **`quote.margin` 在回测中是静态快照**，老合约返回占位值，不可用于动态保证金
- **隐藏 ≠ 移动**：隐藏属性不改路径（程序零影响），移动改路径（按路径查找的代码会静默失效）
- **行尾（CRLF/LF）必须用 `.gitattributes` 固化**，否则 Windows 下 `.bat` 会被
  编辑器写成 LF，导致 cmd 把 `REM` 当命令执行

这些注释数量较多，但它们是本仓库中**最有价值的部分**——它们记录的是无法从代码本身
读出的「为什么」。
