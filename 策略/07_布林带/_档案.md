## 一句话逻辑

**价格跌破布林带下轨就买、涨破上轨就卖，回到中轨平仓。**

**均值回归**型 —— 赌「偏离太远会拉回来」。双向。

## 定稿参数（v4）

| 项 | 值 |
|---|---|
| 周期 | **30 分钟** |
| 指标 | **BOLL(20, 2.0σ)**：中轨 = MA20，上下轨 = 中轨 ± 2×标准差（样本标准差 ddof=1） |
| 开仓 | 空仓 且 收盘 ≤ 下轨 → 开多；空仓 且 收盘 ≥ 上轨 → 开空 |
| 出场 | v1 起改为：**回到中轨另一侧 0.5×半带宽**（不是碰中轨就走） |
| 时间止损 | v2 起：**满 20 根未出场即离场** |
| 硬止损 | v3 起收窄为 **1×ATR**（原 2×ATR） |
| 仓位 | v4：基数 **40 万**、`RISK_PCT 0.30%`（账户 100 万里锁死 60 万不动） |

## ★ 最重要的一条：那个 +10.42% 不能当证据

`PVC_布林带.json` 里 v3 = **+10.42%**，是五个策略在整个 2026 上半年**唯一的正收益**。

但它是这么来的：

```
v0  +2.09%  （裸版）
v1  +2.60%  （出场改「中轨另一侧0.5×半带宽」）
v2  +3.31%  （加时间止损 20 根）
v3 +10.42%  （止损 2×ATR → 1×ATR）
```

**一路在同一个 2026 样本上改，越改越好 —— 这叫过拟合。**

三条硬证据：

1. **2026 IS 是全历史唯一正窗口**（09-22 原话）。
2. +10.42% 由「止损 2.0→1.0」这一**择优动作**取得 ⇒ **不得当 alpha 证据**。
3. 止损收窄后手数自动翻倍（单笔风险仍锁 1%），是**杠杆放大**，不是策略变好。

⇒ 正确理解：**03 定死在震荡区间勉强保本、趋势行情反复逆势亏损。**
2026 是它碰巧对上的环境，不是它的本事。

## ★★ 2026-10-08：engine 防护补强（本轮唯一改过engine 的地方）

07 是**当前唯一活跃的 engine 策略**（05摆动线已冻结）。审查`lib/engine.py`（6540 行）发现：
**全文零命中** `fuse` / `halted` / `熔断` / `重连` / `RECONNECT` / `watchdog`
⇒ engine **完全没有**账户级熔断与会话守护，而 06_MA13 早已把这套做出来了。

### 搬进来的东西（新增文件 `lib/engine_guard.py`）

| 能力 | 类 | 语义 |
|---|---|---|
| 账户级回撤熔断 | `Fuse` | 自峰值回撤 ≥ `DD_FUSE`(20%) → **闩死**，禁止新开仓/反手；**平仓与减仓照常放行** ⇒ 持仓仍有止损保护。峰值与闩锁落`熔断状态.json`，**跨会话持久化，触发后重启不自动复位**（需人工删该文件）|
| 会话异常自动重启 | `RestartLoop` | 断线/被踢/网络异常 → 整体重跑会话体。跨重启不丢：止损线与时间止损计数（`_boll_state.json` 精确恢复）、熔断状态、持仓（以云端真实持仓为准）|

### 为什么用「重启整个入口」而不是「原地重连」

engine 每个 `run_live_*` 在函数开头**自建全部 serials**（klines/quote/account/trade_log/orders/TargetPosTask），
断线后这些对象全部失效。原地重连要逐条抄一遍 7 个对象的重建 + 止损补挂 + 状态恢复，
**漏一条就是静默失效**（持仓裸奔）。重跑整个入口天然走完整启动流程，漏不掉。

### engine 与 ma13 的关键差异（所以engine 不需要 `FIX_WAIT_SEC`）

- ma13 对账方向是「**云端 → 覆盖内存**」⇒ 刚下单时可能被误判为外部遗留持仓，
  所以需要 `FIX_WAIT_SEC=30` 撮合窗口。
- engine 是「**内存 want → 问云端**」（want 是主变量）⇒ 刚下单时 want 已等于目标手数，
  `want == pos_now` 天然成立，**不会误判** ⇒ **不需要撮合窗口**，硬搬反而画蛇添足。

### 接入点（`run_live_boll` 已拆成两层）

```
run_live_boll(...)          ← 外层：建 Fuse + 包 RestartLoop（对外签名不变，5 个入口零改动）
  └─ _boll_session(...)     ← 内层：原函数体（死循环），只用 _fuse 做两件事：
       ① 心跳段：按account.balance 评估熔断
       ② 开仓段：已闩死则把 target 改回 want（= 无动作），只保留平仓/减仓权限
```

**新增参数**（都有默认值，不传也能跑）：
`dd_fuse=0.20` / `fuse_dir=None`（默认取 state_path 或 ledger_dir 同目录）/ 
`guard_restart=True` / `guard_restart_wait=10` / `guard_max_restart=0`（0=无限重试）

**快照考证**：`2026-09-23`、`2026-09-29` 两份代码快照 + `09-27 收档版` **全部是 v4**
⇒ 回测脚本的**值**是在 09-29 之后被改成通用默认值的，**但注释/模拟盘/档案/产物都没跟着改**
（推断为批量改写误伤；证据：只有「值」变了，其余四处全是 v4 文案）。

### 改成了什么

**统一到 06/08 的口径**（用户 2026-10-13 拍板）：

| 项 | 改后 |
|---|---|
| RISK_PCT | **1.0**（= 单笔风险基数×1% = 2000 元；engine 的 risk_pct 是**百分数**） |

**甲醇未动**（出局品种，本就是通用口径，其头部注明「仅作历史留档」）。

### ⚠️ 已知代价（诚实记录，非新发现）

**「波动率预算」退化为「固定 8 手」。** 1×ATR 止损下 4 个品种的手数多数撞上限 8
⇒ 单笔风险随 ATR 漂移 **2.5~4.1 倍**，波动率风控名存实亡。
v4（0.30% × 40 万 / 夹 [8,25]）**正是为修掉这个问题而设的**（风险离散降到 1.0~1.75 倍）。
2026-10-13 为与 06/08 统一口径而回退 ⇒ **该问题已知回归，不是新 bug。**

**实测印证**：PVC IS 第一笔（2021-01-04）即 `开空 8 手`，直接撞上限。

### 口径不变的东西

- **夏普/卡玛不随手数口径变化**（手数只是杠杆刻度，收益率与回撤同比例缩放）
  ⇒ 因此**「跨年 1/20 淘汰」的结论不因本次统一而改变**。
- 策略逻辑（BOLL(20,2σ) / 超调出场 / 20 根时间止损 / 1×ATR）**一字未动**。
