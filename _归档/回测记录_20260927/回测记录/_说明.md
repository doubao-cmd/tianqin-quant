# 回测记录

> **一次运行 = 一个自包含目录，永不覆盖。**
> 用来回答「当时到底跑的什么参数、什么代码、什么区间」——
> 报告里只有结果，配置里才有「怎么跑出来的」。

## 目录结构

```
回测记录/
└── <策略>__<品种>/
    └── <时间戳>_<样本>/
        ├── 说明.md        ← 先读这个（一页纸：区间/快照/备注/成本口径）
        ├── 参数.json      ← 全部参数 + 代码快照指针（机器可读）
        ├── report.html    ← 回测报告（资金曲线 + 逐笔 + 指标卡）
        └── 明细.txt       ← 逐笔成交明细
```

例：`回测记录/布林带__PVC/2026-09-24_232659_IS/`

**为什么两层（先组合、再时间戳）**：一个「策略×品种」的历史自然聚在一起，
翻该组合的演进不用在全项目里筛名字；上层目录名同时就是组合标识。

## 与 `回测结果/` 的分工（两者并存，不互相替代）

| | `回测结果/` | `回测记录/` |
|---|---|---|
| 面向 | **当前状态** | **历史留档** |
| 组织 | 策略/品种 两层 | 组合/时间戳 两层 |
| 覆盖 | 同名**覆盖**，只留最新 + 汇总页 | **永不覆盖**，一次一个目录 |
| 读者 | `工具/汇总报告.py`、`工具/回滚.py` | 人（回查「当时怎么跑的」） |

引擎仍把报告落到 `回测结果/`；`lib/run_record.py` 在跑完后**复制**一份过来归档。

## 怎么产生

组合层跑回测时**自动归档**，无需手动：

```bash
python 组合/布林带__V.py 回测 IS
# → [归档] 回测记录/布林带__PVC/2026-09-24_232659_IS/
```

只要 `组合/<策略>__<品种>.py` 里写了 `跑回测(...)` 与引擎调用，
在末尾接一行 `run_record.归档(...)` 即可（照抄 `组合/布林带__V.py`）。

## 硬要求

1. **`参数.json` 是硬要求** —— 没有它，三个月后看到 `+9.30%` 不知道是哪个参数版本。
2. **代码快照指针必须落在 `参数.json` 里** —— 代码复制在
   `工具/_归档/代码快照/`，归档目录只记「是哪一份」，不重复占空间。
   由 `lib/code_snapshot.py` 在回测开跑前自动产生。
3. 跑**样本外（OOS）**时归档照常，但 `样本` 字段会明确写 `OOS` ——
   样本外只应跑一次，多出来的目录本身就是「被污染过几次」的证据。
4. 淘汰/关键节点的记录**要留**（它们代表走过的路）；纯调试的临时运行可回收。

## 汇总页

跨品种/跨策略的横向对比不塞进本目录，仍由 `工具/汇总报告.py` 生成的
**汇总页**统一呈现（账本在 `工具/_账本/*.json`）。
