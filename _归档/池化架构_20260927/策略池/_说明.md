# 策略池

> **一个策略一个文件夹**（2026-09-27 用户定）。
> 文件夹里只放**纯交易逻辑**，不含任何品种名、不含路径、不含账号。

---

## 现在里面有什么

```
策略池/
 ├─ 通道突破/              ★ 当前唯一在测
 │   ├─ 通道突破.py            纯逻辑（唐奇安突破 + ATR 止损 + 不反手）
 │   └─ _说明.md               在测什么 / 参数 / 版本沿革 / 当前结论 / 报告在哪
 ├─ 布林带/
 │   ├─ 布林带.py              已淘汰，留作分层脚手架对照
 │   └─ _说明.md
 ├─ _模板.py               新建策略照这个抄
 └─ _说明.md               本文件
```

**品种不在这个目录里** —— 品种统一放 `品种池/`，这样一份逻辑才能跑多个品种。

---

## 规则

1. **一个策略 = 一个文件夹**，文件夹名 = 策略短名（`通道突破/`），
   里面的主文件同名（`通道突破/通道突破.py`）。
2. 每个策略文件夹里放一份 `_说明.md` —— 在测什么、参数、版本沿革、**当前结论**、报告在哪。
   **这是「一个策略单个研究」的载体**：打开这个文件夹，这个策略的全部情况都在。
3. **禁止出现品种名**（甲醇/PVC/…）、**禁止出现合约代码**（CZCE.MA/…）。
4. 策略文件只暴露一组入口函数，由 `组合/` 层调用：

```python
参数 = {...}                      # 该策略全部可调参数（一次设定，不扫描择优）

def 算信号(k线表, 参数) -> 信号列:   # 只吃已收盘K线，输出 1/0/-1
def 算手数(权益, atr, 乘数, 参数) -> int
```

5. 策略自己**不扣成本、不算收益**，这些都交给 `lib/engine.py`。
6. 版本演进写在 `_说明.md` 的沿革表里（v0→v1 改了什么、结果如何），**不靠文件名堆版本号**。

---

## 为什么这么做

以前是 `策略/03_布林带/回测/PVC/布林带_PVC.py`，五品种 = 五份几乎一样的代码，
改一次逻辑要改五遍，忘一个就口径不一致（09-23 手数 bug 就是这么漏的）。

现在是**一份逻辑 × N 个品种**：加品种只加 `品种池/` 一个文件，加组合只加 `组合/` 一个文件。

而**每个策略留一个文件夹**，是为了让「这个策略研究到哪一步了」一眼可见 ——
代码、参数、结论、报告位置全在同一个文件夹里，不用满项目找。
